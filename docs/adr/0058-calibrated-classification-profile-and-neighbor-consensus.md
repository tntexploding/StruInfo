# ADR 0058：分类阈值、Profile v2 与邻居共识

- 状态：Accepted
- 日期：2026-09-01
- 决策者：Project owner / Main Agent

## 背景

M2-P2G 在 14,910 条公开当前 Entry 上保持了较高的选择性一致率，但 10,715 条缺类型 Entry 中只有
353 条能由正文体裁规则安全判断；领域仍有 4,266 条缺失。继续整体降低门槛会重新引入工具卡片被
误判为事实资料等已知问题，而把所有剩余项交给 Codex 或人工也不能形成可持续的工程路径。现有外部
分类 Profile 只有统一容量和逐文本包含匹配，既不能表达各类别风险差异，也不适合承载数千条精确
关键词映射。

## 决策

1. **M2-P3A 按类别校准**：类型和领域分别保存每个非 `other` 类别的最低分与领先幅度。明确数据资料、
   个人经历、互动内容和公告使用更保守的类型阈值；已验证的解释、教程、分析、观点和文学强信号保持
   原有可达路径。自动分类继续不得写 `other`，也不得覆盖任何已有类型或领域。
2. **M2-P3B Profile v2**：外部 Profile 增加类别阈值、邻居策略和映射 scope。v1 配置按原语义升级，
   保存时写成 v2；旧个人数据包继续可读。别名上限为 1,024，映射上限为每维 4,096，排除词上限为
   1,024。最多 256 条 `text` 映射可查标题/关键词/正文；大规模映射必须使用
   `content_keyword` 精确匹配。精确映射建立内存索引，别名和排除词正则按 Profile 编译一次，避免在
   每个 Entry 上重复扫描数千条规则。
3. **M2-P3C 邻居共识**：分类上下文只使用当前可见 Entry 的规范内容关键词建立有界倒排索引。默认
   候选至少共享一个关键词、Jaccard 相似度至少 15%、关键词 fan-out 不超过 64，并从最多 12 个邻居
   中要求至少 4 个已有标签及 85% 共识。公开和隐私 Entry 在候选形成前分离；类型不得从同一 Snapshot
   复制，领域可以利用同文档一致性。证据数量、共识比例和 `neighbor_consensus` 来源进入只读诊断。
4. 邻居证据只参与现有确定性分类器。首次 enrichment 可用同一原子 revision 中刚生成的内容关键词
   查询邻居；类型补全预览与正式 enrichment 使用同一上下文。实际写入仍只经过 P0B 的每 Snapshot
   原子 revision、规则摘要、失败恢复与增量 Association 重建，不增加第二套 writer、迁移或 Provider。
5. 提供 `classification:m2-p3:evaluate` 只读工具。输入位于外部临时文件，输出仅含数量、basis-point
   覆盖率和一致率，不输出标题、正文、来源或 Entry ID。代码完成不得自动 refresh 或 apply 所有者数据。

## 实测校准

在所有者授权的本地 PostgreSQL 18.6 私人部署上，对 14,910 条公开当前 Entry 进行了临时导出后的
内存只读回放；容器和宿主临时文件在命令结束时删除，数据库没有写入。

- 类型已有标签 4,195 条；新组合对其中 2,346 条给出预测，2,162 条与现值一致，选择性精确一致率
  为 92.16%。其中 58 条使用邻居证据，53 条一致，邻居子集为 91.38%。
- 10,715 条缺类型 Entry 中可预测 355 条，其中 48 条来自邻居共识；预计总类型覆盖为 30.52%。这只比
  P2G 的 353 条多 2 条，但用高一致邻居替换了部分低置信度体裁猜测，因此本阶段不宣称类型覆盖发生
  大幅提升。大规模类型提升仍应来自外部精确映射、P2E Codex 工作包或类型体系后续调整。
- 领域已有标签 10,644 条；选择性 exact-set 一致率为 91.52%，至少一项重叠为 97.23%。邻居子集的
  exact-set 为 90.69%，重叠为 97.87%。4,266 条缺领域 Entry 中可补 242 条，预计总领域覆盖从
  71.39% 提升到 73.01%。

这些是现有标签回放而非独立人工金标。它们用于选择默认门槛，不授权修改外部工作区，也不证明所有
类别分布已经完善。

## 边界

- Profile、个人映射和评测输入仍是外部个人数据，不进入 Git、数据库规则表、日志、镜像或 fixture。
- 邻居共识是可解释的弱监督分类信号，不是语义关系、正式知识边或人工确认事实。
- 不基于同一 Snapshot 的类型标签自我复制，不让高频关键词形成无界候选，不跨隐私范围计数。
- 本增量没有 migration、新依赖、Provider、后台循环或自动 apply。真实写入仍需所有者另行授权、停写
  备份、有限窗口执行和抽样复核。
