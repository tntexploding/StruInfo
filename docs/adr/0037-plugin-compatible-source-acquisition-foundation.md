# ADR 0037: 插件兼容的外部信源获取与入库底座

- 状态：Accepted
- 日期：2026-08-27
- 里程碑：M1I-1A / M1I-1B

## 背景

当前产品已经可以定时检查一个精确公开 GitHub Markdown 文件，并复用 Evidence、外部 Blob、Snapshot、Fragment、可选确定性物化和自动分流主链。RSS/Atom、声明式 API 和网页订阅若各自直接写数据库，会产生三套游标、去重、隐私和失败恢复逻辑，也会让未来插件绕过产品权威。

上线前的外部信源阶段需要先建立一个共同边界：内建读取器与安装后的插件适配器只负责取得内容，主程序继续负责订阅状态、调度、隐私、入库、游标和后续处理。

## 决策

### M1I-1A：统一获取结果与连接器注册

服务端增加 SourceConnectorPort 与 SourceConnectorRegistry：

- 每个内建读取器或插件适配器使用稳定 connectorId 注册；
- 连接器配置属于包体外个人数据，连接器凭据不得进入 Git、数据库正文、个人数据包或普通日志；
- 连接器只能返回 unchanged，或返回一个带新游标的有界文档集合；
- 每份文档必须给出稳定外部身份、版本、HTTPS 规范链接、媒体类型、UTF-8 Markdown 投影以及可选精确原始字节和发布时间；
- 每批最多 64 份文档，每份原始字节和文本投影各不超过 1 MiB；
- Registry 对输出做闭合验证、复制和冻结，未知连接器、重复连接器、畸形结果和超预算结果均稳定失败；
- 连接器没有 Evidence、Entry、标签、联系、正式图谱、AI 提案或个人偏好写端口。

“插件兼容”只表示安装的受信任适配器可实现相同端口。网页正文、RSS 条目、API 响应或插件返回值始终是不可信数据，不能携带可执行指令、工具权限或数据库命令。

### M1I-1B：统一远程文档入库

前向迁移 000023 只给既有 Resource.resource_kind 闭合枚举增加 remote_document，不修改已有行。

通用入库准备器：

- 由 workspace、subscription、connector 和外部文档身份派生稳定 Resource；
- 由原始字节与 Markdown 投影摘要派生稳定 Snapshot 和命令身份；
- 原始远程字节继续进入包体外内容寻址 Blob，Markdown 投影继续进入既有 CommonMark/Fragment 主链；
- 多文档批次按稳定顺序逐份写入；只有全部成功后，上层订阅服务才可以推进游标；
- 中途失败可以留下已经成功的幂等 Snapshot，但重试不会复制这些 Snapshot；
- 隐私由主程序订阅配置决定，连接器不能自行扩大或缩小隐私范围。

本阶段只完成连接器与入库底座。现有 GitHub 订阅仍是唯一公开可配置的远程订阅；RSS/API/网页读取器、其外部配置 union、公开 API 和导入页控件由后续 M1I-2 至 M1I-4 逐项接通，不能提前显示为可用。

## 上线前后续顺序

1. **M1I-2 RSS/Atom**：公开 Feed、条件请求、条目游标、HTML 正文清洗和逐条入库；
2. **M1I-3 声明式 JSON API**：只读 GET、闭合字段映射、分页/增量游标和逐记录入库；
3. **M1I-4 受限网页订阅**：单页或同源显式范围、正文投影、变化检测和频率限制，不做开放网络发现；
4. **M1I-5 插件接线**：让受信任插件通过相同 Registry 交付文档，不允许插件直接写产品状态。

完成外部信源阶段后，按所有者指定的上线前优先级依次处理正式知识深化、分词/向量/RAG、性能评估与优化，以及容器、维护和生产边界。其他体验与扩展在引入真实资料后的实际使用中选择性推进。

## 非目标

- 不在本阶段抓取真实网页、Feed 或 API；
- 不恢复真实文档、个人偏好或历史数据库；
- 不实现登录态抓取、绕过反爬、浏览器自动化、开放网络发现或仓库代码执行；
- 不把 Provider、Embedding、RAG、向量数据库或正式知识写入混入连接器；
- 不把插件配置、抓取正文、游标或凭据写入 Git 或应用包体。
