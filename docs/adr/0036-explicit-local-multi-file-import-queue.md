# ADR 0036: 显式本地多文件导入队列

- 状态：Accepted
- 日期：2026-08-27
- 里程碑：M1H-5A / M1H-5B

## 背景

导入页已经可以逐份选择 Markdown、纯文本、HTML 或带文字层 PDF，并把每份文件接入现有 Evidence、外部 Blob、隐私和幂等导入边界。连续录入一组已经由所有者明确选中的文件时，逐份重新打开文件选择器和等待证据面板跳转会产生不必要的操作成本。

多文件选择只是同一现有导入能力的批次编排，不应因此引入目录扫描、后台采集、第二套存储或自动下游处理。

## 决策

### M1H-5A：显式多文件选择与逐文件请求

导入页的“本地文件”来源增加“单份文件 / 多份批次”切换：

- 一次最多接受所有者明确选择或拖入的 20 份文件；
- 每份文件继续独立遵守现有扩展名、普通文件名、1 MiB、UTF-8/有效 PDF 标识和内容规则；
- 浏览器只读取显式选择的文件，不读取目录、相对路径、子目录或机器路径；
- 每份文件在加入队列时获得独立的 command、Resource、Snapshot 和 capture 身份；
- 每份文件使用文件名与精确内容 SHA-256 生成默认来源身份，不把一份别名或规范链接错误套用到整批文件；
- 不得仅凭文件名、大小和修改时间丢弃选择项；这些元数据相同但内容不同的文件仍是两个独立条目；
- 隐私、发布日期、Markdown profile 和可选前置文字是本次批次的显式公共设置；非 Markdown 文件仍使用既有确定性投影规则；
- 每项复用与单文件完全相同的公开导入请求，不新增批次写协议。

### M1H-5B：会话队列、逐项结果、重试与停止

导入页维护一个浏览器会话内队列：

- 显示准备、就绪、写入、成功、失败、无效和已停止状态；
- 显示完成数以及成功、失败、已停止计数；
- 按顺序逐份发送，成功项不会因为其他项失败而回滚；
- 失败重试复用已经冻结的请求和原 command/Resource/Snapshot 身份；
- “停止后续导入”不会伪装成已经中断当前 HTTP 写入；它只在当前项结束后阻止后续项开始；
- 队列有内容时，来源类型和单份/批次切换保持锁定，必须先清空队列；运行期间公共隐私、日期、解析规则和前置文字保持锁定；
- 批次成功后只统一刷新一次材料列表，不为每个成功项反复打开证据侧栏。

队列本身不写数据库、偏好或个人数据包，页面刷新后消失。它不是 ProcessingRun，也不进入总览任务轨道；数据库仍只保存真正完成的逐文件 Snapshot。

## 存储、隐私与兼容性

本阶段没有迁移、新表、新 API 路由、新依赖或 Bundle 分区。原始和投影字节仍由现有服务写入包体外 Blob，元数据仍进入现有 PostgreSQL Evidence 表。隐私事实逐项传入原导入边界并继续向后续 Entry 与联系传播。单文件导入行为保持兼容。

## 非目标

- 不扫描文件夹，不读取目录，不监听文件系统；
- 不增加 Office、OCR、复杂 PDF 视觉还原或云盘同步；
- 不建立持久后台上传任务、断点续传或跨页面队列恢复；
- 不在导入成功后自动物化 Entry、生成标签、建立联系、接受 AI 提案或运行 AutomationPolicy；
- 不恢复真实资料，也不把文件、偏好或队列内容写入 Git 或应用包体。
