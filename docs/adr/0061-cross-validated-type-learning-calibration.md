# ADR 0061：正文特征、Snapshot 交叉验证与目标精确率校准

- 状态：Accepted
- 日期：2026-09-02
- 对应增量：M2-P4E
- 修订：在 ADR 0059/0060 的可信样本、类别均衡和全量投射边界内升级模型；不改变 Entry 写入权威

## 背景

M2-P4D 关闭了类别不均衡、零样本平滑和全量投射坍缩问题，但候选模型仍主要依赖标题、内容关键词、
长度与少量结构信号。正文中可复用的短语和字形没有被充分利用，旧阈值也来自正样本分数分位数，而不
是直接寻找满足 92% 目标精确率的分数和领先幅度。每类 64 条训练上限若只按稳定顺序截取，还可能遗漏
模型最难区分、最值得保留的样本。

## 决策

1. 特征版本升级为 `struinfo.entry-type-learning.features.v2`。除原有特征外，只读取正文前 4,096 个
   Unicode code point、前 96 个词项，并分别保留最多 48 个词项、64 个相邻短语和 64 个字符 trigram。
   选择过程稳定且有界；模型只保存特征名和整数权重，不保存正文、向量或 Provider 数据。
2. 一个特征必须至少出现在同类 2 个可信样本和 2 个不同 Snapshot 才能产生权重。权重继续使用正负
   Snapshot 观测率差，并在达到 4 个正 Snapshot 前按支持量缩减；负差、低于 500 的弱特征和超过每类
   128 个的尾部特征不进入模型。零样本和支持不足类别仍然禁用。
3. 影子评估改为按 Snapshot 整组分配的类别均衡三折交叉验证。同一 Snapshot 的 Entry 只能同时位于
   某一折的训练侧或验证侧，不能跨侧泄漏。每个可信样本恰好产生一次 out-of-fold 结果；评估不再依赖
   单个固定留出 Snapshot 集。
4. 每个支持类别直接在 out-of-fold 结果上搜索 `minimumScore` 与 `minimumMargin`，先最大化满足条件
   的赋型数量，再最大化 precision；所有可执行类别和全局 precision 都必须达到 9,200 basis points。
   同等覆盖和 precision 时选择较低的合格阈值，避免只记住完整训练特征组合。原有 15% 验证覆盖和
   全量缺类型投射的覆盖、类别数、单类占比门继续生效。
5. 评估增加稀疏混淆矩阵和最多 64 个已赋型误判身份。误判只包含 Entry/revision/Snapshot、预期类型、
   预测类型、分数和 margin，不包含正文。现有 `type-learning apply` JSON 结果直接携带这些诊断，供下一
   轮 Codex/人工标注选择困难样本和修正规则，不新增第二个导出协议。
6. 最终训练每类仍最多 64 条。先用全部可信行建立临时可解释模型，按错误预测、无信号、低 margin 和
   低分排序；每类先保留最多 48 条最困难样本，再补尚未代表的 Snapshot，最后按稳定顺序填满余量。
   训练上限因此控制成本，但不再等同于“取最早 64 条”。
7. 激活策略升级为 `struinfo.entry-type-learning.activation.v3`。P4D 的 feature v1 / activation v2
   模型和更早状态继续可读取、备份和恢复，但不能进入当前候选排序或正式分类，必须使用原可信样本重训。

## 后果

- 正文中的短语和字形可以提高不同写法下的覆盖，同时 Snapshot 支持门抑制偶然词和单文档特征；
- 阈值、混淆和误判都直接对应 92% 精确率目标，下一轮标注可以优先处理真实困难样本；
- 旧可信样本不会被删除，现有 Entry、标签、联系和知识图谱不会被本轮自动修改；
- 本增量没有迁移、新依赖、Provider/API、UI、后台任务或真实数据操作，正式激活和补全仍需所有者显式执行。
