# ADR 0065：五步主线发行回归

- 状态：Accepted
- 日期：2026-09-03
- 对应增量：M2-P5D
- 修订：扩展既有一次性 PostgreSQL 18 合成回归；不引入真实资料或第二套产品实现

## 背景

首版之后的 M2 批量处理、分类和生产维护能力分别已有自动化证据，但决定下一发行候选前仍需要一条
覆盖当前产品主线的同库回归。该回归必须证明导入、拆分、标签、联系、查询和知识展示能够在正式迁移、
runtime grant、失败恢复和当前索引下共同工作，同时不能连接所有者现有数据库或把真实资料带入仓库。

## 决策

### 1. 复用唯一的一次性 PostgreSQL 工具

既有 `performance:m2-p0d` 工具升级为报告 v2。它继续创建随机命名的 PostgreSQL 18.6 容器、随机本地
端口和临时外部数据根，并在成功或失败后清理。smoke 使用 4 个 Snapshot / 32 个 Entry；标准回归使用
500 个 Snapshot / 15,000 个 Entry。所有输入均为合成、无个人含义的值。

### 2. 同一工作负载贯穿完整产品主线

回归依次执行：

1. 全部迁移、队列准备、runtime grant 和 preflight；
2. 正式 Evidence/Blob 导入与 P0A Entry 拆分，包括一次受控失败、重试和重放；
3. P0B 确定性标签与增量联系，包括一次受控失败、重试和重放；
4. P0C 异常裁决与 stale/count guard；
5. 当前搜索投影重建、词法查询、精确 Fragment 来源返回；
6. 以查询匹配 Entry 为中心构建有界知识图；
7. 通过 M2-P5C PostgreSQL observer 核对当前 Entry 与搜索投影完整性。

任何阶段失败都返回稳定、脱敏的失败 stage，不把正文、URL、密码或宿主个人路径写入报告。

### 3. 发行证据由三层组成

下一候选至少同时通过：

```text
corepack pnpm run verify
corepack pnpm run test:e2e
corepack pnpm run performance:m2-p0d -- --smoke
```

发布前需要更强规模证据时再执行标准 15,000 Entry 回归。固定 commit、镜像构建/扫描、真实部署升级与
外部备份复核仍属于随后的发行操作；本 ADR 不自行创建 commit、tag、release 或推送远端。

### 4. 证据边界

该链证明当前代码在一次性 PostgreSQL 18 上的主线一致性和可恢复性，不证明所有者云主机的域名、
镜像摘要、防火墙、认证、真实资料质量、长期容量或 Provider 费用。生产实例的实际升级仍须使用 Git 外
的配置和运维记录，并在升级前后执行备份验证。

## 结果

- M2 批量管线不再只由独立模块测试证明；查询和知识读取纳入同一次数据库回归；
- 搜索投影计数、匹配结果、来源返回和知识邻域成为发行候选的明确证据；
- 失败恢复、runtime grant 和资源清理继续复用已有产品边界；
- 真实资料、生产数据库和现有 Docker 资源不会被测试读取或修改。

## 验证

- smoke 回归实际完成 4 Snapshot / 32 Entry 的完整链和资源清理；
- 标准回归实际完成 500 Snapshot / 15,000 Entry、15,000 个当前搜索投影、13,500 个词法匹配和 13 节点/12 边知识图，总耗时约 18 分 9 秒；
- 报告核对 Resource、Snapshot、Fragment、Entry、规则关键词、Association、异常裁决和搜索投影计数；
- 词法查询返回合成匹配项和精确 Fragment input，知识图返回有界节点与边；
- PostgreSQL 运行观测确认当前 Entry 与当前搜索投影数量一致；
- 30 份迁移的首次执行和 exact no-op 重放、P0A/P0B 受控失败恢复、P0C 数量保护以及一次性资源清理均通过；
- 该耗时是当前机器上的合成工程证据，不是云端 SLO 或真实资料质量证明。
