# ADR 0066: 可恢复的公开 Entry 增量索引维护

- 状态：Accepted（已实现）
- 日期：2026-09-05
- 对应任务：路线图第 2 项

## 决策

Query 增加用户显式启动的增量刷新。每次 HTTP 请求最多处理 32 个公开当前 Entry 或退役投影；
数据库先按当前 revision、tokenizer 和已配置模型选择变化项，只装载这个窗口的内容和旧投影。
未变化项直接复用。变化项的有界 Provider 输入摘要与旧投影相同且模型相容时，复用旧向量并更新词项与版本。
没有 Embedding 配置时，刷新只需完成本地词项路径。

已提交的逐项投影就是恢复检查点，不新增任务表、后台调度、进度文件或个人数据包部分。
页面可连续请求有限窗口，并在本批结束后暂停；关闭页面、请求失败或进程重启后，下一次显式刷新重新查询剩余变化项。
不把页面会话状态伪装为 ProcessingRun，也不要求还原历史浏览器游标。

一个 API 服务实例串行执行索引维护，重复在途请求返回明确的忙状态。
每个窗口的投影和词项在现有 workspace write lock 下原子保存；提交时重新核对公开范围、当前结构和精确 revision，
过期结果不会覆盖新 Entry 状态。退役或改为私密的投影按相同窗口预算清理。
Provider 只接收本次读取时仍公开的条目；调用期间发生的修改在保存时拒绝，并留给后续刷新。
索引失败不能阻断原有完整词法查询。

Provider 失败时可以保存已完成的本地词项和可复用向量，并返回明确失败原因及剩余数量；
再次刷新仅处理仍需生成的向量。网络结果不确定时，失败窗口可能再次请求 Provider，不承诺外部调用恰好一次。
不新增第二 Provider、私密外发、自动索引权限、依赖或数据库迁移。

现有全量重建作为显式修复入口保留，继续原子替换整个索引，并在提交前校验当前 Entry。
增量识别缺失投影、revision/tokenizer/模型变化、缺失向量和失效的模型元数据；任意词项或向量内容损坏可通过全量重建修复。候选选择只比较元数据，不为每个窗口重新校验全库向量内容。
派生索引仍不进入个人数据包；恢复后由相同增量路径重新建立。

## 验证范围

合成测试覆盖单项变化、无关编辑的向量复用、有限窗口与重启继续、Provider 失败重试、
并发修改与隐私收窄、退役清理、模型变化、词法保底以及全量修复。
真实 PostgreSQL 演练记录候选装载量、更新量和 Provider 输入数量；
浏览器验证显式启动、暂停、继续、失败状态、迟到响应和规定宽度。
真实费用、真实召回质量、私人实例升级和多实例 Provider 调度不在本次开发验证范围。

实施入口、合成验证结果和运行限制见[增量索引维护交付记录](../incremental-index-maintenance.md)。
