# ADR 0062：生产发行身份与已上线状态基线

- 状态：Accepted
- 日期：2026-09-02
- 对应增量：M2-P5A
- 修订：只同步发行、开发与运行状态；不改变产品运行时、数据模型或部署拓扑

## 背景

StruInfo 已发布公开 `v0.1.0`，所有者也已确认同一产品以 Docker 形式运行在私人云服务器上。
与此同时，仓库主开发线已经继续完成 M2-P0 至 M2-P4 的后续工程工作。此前部分文档仍把目标云端写成
“待部署”，也没有清楚区分公开发行、当前开发代码和实际运行实例，容易让后续维护误把三者当成
同一个可替换身份。

本阶段没有取得也不需要把真实域名、证书、认证配置、数据库地址、数据根、备份位置或凭据写入
仓库。M2-P5A 的目标是先建立可复核的状态基线，为后续备份恢复、监控和生产回归工作提供共同起点。

## 决策

### 1. 三种身份分别记录

- **公开发行身份**：Git 标签 `v0.1.0` 指向提交
  `3100567265b70e32c1d903b165d3d2248815a968`，源码树为
  `6f02768158a9030b1332ea8dab4c1249dd66a68d`。
- **内部发行等价身份**：当前开发历史中的提交
  `926a5c2ee791fada443796e3b39f927c8e8c8b51` 具有同一个源码树
  `6f02768158a9030b1332ea8dab4c1249dd66a68d`。公开历史与当前内部开发历史不要求具有祖先关系；
  内容等价性以该树身份为证据。
- **M2-P5A 开发输入身份**：提交
  `86066009193c98bc65088827faa0cbf5204c41a4`，源码树为
  `e6aba30c16104f5f69c507926d44a531e7f4e2cb`。它包含公开首版之后的 M2 工程增量，不能继续标记为
  `v0.1.0`，也不自动代表云端已经运行这些增量。

### 2. 上线状态按证据来源表述

- **已发布**表示公开 Git 标签及其固定源码树存在。
- **已上线**表示所有者已明确确认私人云服务器上的 Docker 实例投入使用。这是运行状态记录，
  不是本次任务对主机、网络、证书、镜像摘要或数据的独立检查。
- **已独立核验**只用于仓库中已经记录实际执行证据的检查。没有取得当前主机证据的项目继续写为
  “待生产复核”，不得因为所有者确认上线就自动标记通过。

### 3. 生产细节继续留在仓库之外

真实域名与 IP、证书和认证材料、防火墙规则、镜像 digest、运行配置、数据库 URL、个人资料、数据根、
备份清单、告警目标和恢复演练结果只保存在所有者的外部运维记录中。仓库只保存无秘密的模板、流程、
稳定版本身份和验证结论。

### 4. P5 后续顺序

1. `M2-P5B`：核对生产备份保留、可恢复性和恢复演练记录；
2. `M2-P5C`：补齐运行监控、容量阈值和故障发现边界；
3. `M2-P5D`：以合成或所有者明确授权的数据执行五步主线生产回归，并形成下一发行候选。

冻结的 `M2-P4R` 类型学习泛化仍不启动，也不阻塞 P5。只有所有者明确恢复并提供独立代表性评测集时，
才重新进入该项。

## 结果

- 项目文档不再把所有者已经完成的私人云端部署描述为“尚未部署”。
- 公开 `v0.1.0` 与后续 M2 开发线不会被混写成同一发行版本。
- 云端部署细节和个人数据不进入 Git；后续 Agent 不得根据本 ADR 猜测这些值。
- 本增量不修改应用代码、容器清单、迁移、依赖、外部配置或任何用户数据。

## 验证

- 公开标签提交、内部等价发行提交和当前开发输入提交均通过 Git 对象身份核对；
- 两个发行提交的 tree identity 相同；
- 本次变更只涉及项目文档，不读取或修改实际生产数据与秘密。
