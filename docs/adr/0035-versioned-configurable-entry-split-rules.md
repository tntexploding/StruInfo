# ADR 0035: 版本化可配置 Entry 拆分规则

- 状态：Accepted
- 日期：2026-08-26
- 里程碑：M1H-4A / M1H-4B

## 背景

现有拆分页已经具备按 section 的确定性物化、人工 Fragment/Unicode 标量分组、可选 AI 提案、拆分前派生全文和物化后结构重组，但普通本地规则仍固定为“每个 section 一个 Entry”。用户需要能够替换日常规则，而不应通过修改源代码、提交脚本或引入 Provider 才能调整短段合并行为。

规则是个人工作方式，不是文档证据或数据库知识内容。它必须保存在仓库外的工作区个人配置中，并通过现有个人数据包随其他偏好迁移。

## 决策

### M1H-4A：外部版本化规则与确定性试算

增加一个独立 `EntrySplitRuleProfile`：

- 默认模式 `one_section` 精确保留原有行为；
- 可选模式 `merge_short_adjacent` 只按来源顺序合并相邻短 section；
- 参数只包括期望最短字符数、允许最长字符数和单组最多 Fragment 数；
- Profile 使用乐观 revision，并与快捷标签、别名、联系策略等兄弟字段一起原子保存在外部个人偏好文件；
- 旧偏好文件或旧个人数据包缺少该字段时补为 revision 0 的默认规则；
- 试算只读取一个精确 Snapshot 的本地 Fragment，返回有界分组、标题、字符数和正文摘要，不写数据库。

规则不会切断单个不可分的 Fragment。若一个源 Fragment 自身超过配置上限，预览明确标记超限；用户可改用既有人工标量范围工具。

### M1H-4B：拆分页编辑、预览与应用

拆分页新增次级规则面板：

- 用户可以编辑草稿、显式保存工作区规则、对当前文档预览；
- 只有与当前保存版本完全一致的预览才能应用，未保存草稿不能写入 Entry；
- 服务端在应用时重新加载同一 Profile revision、重新从不可变 Evidence 计算分组，并调用既有空 Snapshot 原子物化边界；
- 已有 Entry 或拆分前全文工作副本的 Snapshot 不提供该首次物化操作；
- 私密 Snapshot 的预览和应用都要求当前请求明确 `includePrivate`；
- 文档切换或请求重叠时，旧响应不得覆盖当前页面状态。

## 存储与可移植性

本阶段不增加数据库迁移、依赖或新的 Bundle 分区。个人数据包已经携带完整工作区偏好对象，因此新 Profile 随该对象导入导出；旧包恢复时使用默认规则。Snapshot、Fragment、Blob 和已物化 Entry 不被规则保存操作修改。

## 非目标

- 不执行用户脚本、正则程序、插件或自定义解析器；
- 不重排来源，不跨 Snapshot 合并，不自动切断 Fragment 内部；
- 不批量改造已经物化的 Entry，不覆盖 M1H-2 人工重组；
- 不调用 Provider，不自动接受 AI 提案，不向外发送私密内容；
- 不增加规则历史、行为学习或后台自动拆分。
