# ADR 0059：可信样本驱动的 Entry 类型学习 Profile

- 状态：Accepted
- 日期：2026-09-01
- 对应增量：M2-P4A–P4C

## 背景

M2-P3 的按类别阈值、精确映射与邻居共识把类型选择性一致率维持在约 92%，但真实缺类型覆盖仍只有
约 30.52%。继续堆叠仓库内正则会快速增加维护成本，也不能利用所有者和 Codex 已确认的少量高质量样本。

## 决策

1. 类型学习只接受显式可信样本。样本记录 Entry、revision、Snapshot、非 other 类型和
   manual/codex_accepted 权威；自动规则、邻居或模型预测不得反向成为训练样本。
2. 外部分类 Profile 升级为 v3，保存有界可信样本、候选模型和已激活模型。该状态位于外部个人偏好文件，
   自动随个人数据包携带，不进入 PostgreSQL、Git、应用包或日志。
3. 训练使用可解释的稀疏特征：内容关键词、标题词、分块方式、长度桶以及有限结构/语气特征。每类保存
   有界正权重、最低分和领先幅度，不保存正文、Prompt、Provider JSON 或不可解释向量。
4. 训练/验证按 Snapshot 分组，避免同文档泄漏。候选模型先输出影子 precision/coverage 和逐类指标；
   只有全局精确率不低于 92%、已赋型类别不低于 85% 且存在真实验证赋型时才可显式激活。
5. 运行时顺序固定为：现有精确映射/确定性规则 → 已激活本地模型 → 邻居共识 → 保持未分类。
   模型不得覆盖已有类型，也不得自动产生 other。
6. 当前开发周期复用外部 codex-work 文件区：维护命令导出主动抽样包，Codex/所有者填写封闭结果，
   import 只更新外部 Profile 并训练候选，不直接改 Entry。显式激活后，正式补全继续复用 P0B/P2G
   的原子 revision、恢复、规则摘要和增量联系路径。
7. 后续 API 适配只能复用同一 packet/result 与 Profile 激活边界；不得建立 Provider 专用训练状态或
   让 Provider 直接写 Entry。

## 后果

- 少量确认样本可以持续形成可变、持久、可回滚的类型规范；
- 不合格候选只停留在影子状态，不影响现有分类；
- 本增量没有迁移、新依赖、后台任务、Provider 调用或真实资料；
- 首次对所有者数据导出样本、激活模型和补全 apply 仍需分别显式执行。
