# ADR 0064：运行健康、容量与告警边界

- 状态：Accepted
- 日期：2026-09-03
- 对应增量：M2-P5C
- 修订：增加只读运行状态报告；不增加迁移、后台守护进程或远程通知器

## 背景

M2-P5B 已能盘点和验证外部备份，但运行中的私人实例仍缺少一个稳定、可由宿主定时调用的状态入口。
单独的 `/health/ready` 只能说明当前数据库准入，不足以同时发现索引未完成、处理任务失败或停滞、
备份过旧以及外部数据根空间不足。另一方面，真实告警目标、主机路径和生产容量属于外部运维状态，
不应写进仓库或成为新的产品数据库。

## 决策

### 1. 一个只读维护状态入口

维护 CLI 新增：

```text
maintenance status
maintenance status --max-backup-age-hours <1..8760> --minimum-free-percent <1..99> --max-running-age-minutes <1..10080>
```

缺省阈值分别为 168 小时、10% 和 60 分钟。命令不写 Evidence、Entry、Association、Processing、
偏好、Blob 或备份；状态为 `ready` 时退出 0，发现需要处理的告警时退出 1。外部调度器和监控系统可
依据退出码及稳定告警码决定通知方式。

### 2. 有界且脱敏的观测

数据库观测在只读可重复读事务内一次取得数据库/证据 Blob 字节数、主要领域计数、当前 Entry 与
当前搜索投影计数、失败或长时间运行的 ProcessingRun、失败批次以及待处理提案/所有者工作项。
外部数据根只报告总容量、可用字节和可用百分比；备份只报告当前 workspace 最新合法文件的时间、
年龄和字节数。报告不包含 URL、密码、绝对路径、正文、标签值、偏好内容或备份内容。

### 3. 观测彼此独立并使用稳定告警码

数据库、数据根容量和备份检查分别执行。一个来源失败不能伪造其他来源正常，也不能阻止已经取得的
安全汇总被报告。当前稳定告警覆盖：数据库不可用/观测失败、数据根观测失败/低空间、备份观测失败/
缺失/过旧/未来时间戳、处理失败/停滞以及搜索索引不完整。

### 4. 调度和通知留给部署环境

本增量不增加常驻轮询、HTTP metrics、邮件、Webhook、云监控 SDK 或通知目标。私人本地/云端部署可
使用现有宿主 scheduler、容器任务或监控系统定时执行同一命令。真实阈值选择、告警目的地和处理记录
只保存在 Git 外的运维配置中。

## 结果

- 数据库 readiness 之外的主要容量和恢复风险获得统一可见入口；
- 索引缺口、处理失败/停滞、备份年龄和低磁盘空间不会只靠人工发现；
- 状态观测不会成为第二套产品状态，也不会泄露个人资料或部署秘密；
- 初始化运行配置本身失败时，维护进程仍以失败退出，外部监控必须把非零退出视为需要处理。

## 验证

- 纯函数回归覆盖正常、各告警阈值、未来备份时间以及各 observer 独立失败；
- PostgreSQL adapter 回归固定只读事务、参数和闭合数字映射；
- 文件系统回归覆盖容量换算与失败；
- maintenance 回归覆盖默认/显式阈值、退出语义和脱敏报告；
- M2-P5D 的 disposable PostgreSQL 18 回归实际执行该数据库观测，并验证当前 Entry 与搜索投影完整。
