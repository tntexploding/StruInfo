## 使用方式

从“知识 → 来源复核”进入，默认显示公开范围的待处理关系。
可筛选尚未核对、需要复核、已核对当前版本或全部可见关系；每批 20 条，有上一批和下一批。
列表保留自动、用户或 AI 来源标记，选中项显示关系方向、当前两端条目和原文入口。

分别查看两端精确来源，选择本次核验状态，填写最多 500 个字符的维护说明，再点“保存并继续”。
成功后重新读取并移至下一项，跨批继续使用当前筛选范围。版本冲突会保留失败提示，要求重新读取后核对。
筛选或隐私范围变化立即清除旧详情和来源，迟到的读取、保存或来源响应不能把旧内容带回页面。

“已核对来源”只记录用户检查过当前两端版本，不表示客观事实已被证明。
任一条目后来修订，即使只改标签或评分，原核验记录也会显示“需要复核”；显示上次记录版本和当前版本供判断。
旧核验没有版本信息时保留原状态和说明，按“需要复核”展示，不猜测历史核验对象。
隐藏关系不出现在复核列表；返回图谱后可以使用原有显式恢复操作。

## 数据与接口

迁移 `000031` 在现有关系 override 表增加两个可空正整数：
`graph_reviewed_entry_low_revision` 和 `graph_reviewed_entry_high_revision`。
它们要么同时为空，要么同时有效；没有历史回填或新增表。

| 入口                                                                       | 职责                                   |
| -------------------------------------------------------------------------- | -------------------------------------- |
| `POST /api/v1/knowledge-graph/source-reviews`                              | 按筛选、隐私和游标读取有界关系列表     |
| `PUT /api/v1/knowledge-graph/edges/:entryId/:relatedEntryId/source-review` | 校验显示版本，只更新核验状态和维护说明 |

列表接受 `filter`、`privacyScope`、`limit` 和可选 `after`。默认 pending/public/20，最多 50。
privacyScope 为 public/include_private/private_only，最后一种要求两端均为隐私条目。
游标绑定筛选和隐私范围，并按规范排序的 Entry 身份对前进。
SQL 在计数和分页前排除隐私不可见、退役、隐藏和无当前关系的记录，仅装载当前批及一个前瞻关系的端点正文。

写入接受 `expectedRevision`、`includePrivate`、`expectedEntryRevisions`、`verificationStatus` 和 `note`。
expectedEntryRevisions 包含按规范身份顺序显示的 entryLowRevision/entryHighRevision。
服务先检查当前可见关系，再在同一工作区锁内重新检查端点结构、隐私、版本、关系可见性及 override 版本。
旧请求不会覆盖新修订，不会借复核恢复隐藏边。写入保留名称、关系语义、方向、AI/用户/计算来源及人工调整。

普通图谱编辑在记录来源核验时也发送两端版本；隐藏和恢复保留绑定。
计算投影重建不修改 override。结构重组产生的新关系保留说明与原状态，但不继承不同 Entry 身份的核验版本。

Association Bundle v5 保存两个字段；v1–v4 升级时补空，工作区传输仍为 66 张表。
本轮没有新增依赖、Provider、自动事实判断、网络核验、隐式历史或旧 M1C Knowledge 运行时。
应用数据库须通过既有迁移入口应用 `000031` 后使用新接口；本轮只迁移一次性合成数据库，没有升级正在运行的用户实例。
