# 订阅与新资料自动处理

## 使用流程

在**源管理**添加来源，保存检查方式和接收参数。收到的原文进入底部接收记录。
人工审核后可接受并整理，也可交给 AI 审核。不确定的资料保留原因，等待人工处理。

新文档任务依次执行：

1. 审核接收；人工已接受的决定保留。
2. 按已冻结的来源拆分方案整理结构。连贯文章保留完整，合集拆成独立条目。
3. 生成标签与结构化标注，保存正文依据。
4. 检查修订并确认发布，内容进入查询、问答和报告选材。

主题与重点联系单独排队。它们使用选定的预算，不阻塞基础发布，失败也不撤回正文。
具体操作见[主题与重点联系](content-topics.md)。

## 启用自动处理

1. 按[运行配置](runtime-configuration.md)设置模型和仓库外密钥文件。
2. 在**设置 → AI 执行**设置并发、有限重试和价格时段。
3. 在**设置 → 自动处理**选择来源、手动导入范围、审核规则和每日数量，保存策略。
4. 在**总览**允许 AI 操作，查看任务的等待原因与进度。

自动处理默认关闭。只接管启用范围内的新资料；历史补收默认待审核，旧失败任务不会因升级自行继续。
未配置模型时，可以保存关闭或暂停的策略。单篇额度包含模型尝试和允许的重试。
私密材料不发送给模型。

使用一个 `all` 进程即可完成采集和队列处理；不必保持浏览器开启。
每次模型请求前仍检查全局许可、价格时段、并发和预算。
允许 AI 操作只解除总控，不扩大来源范围，也不重置耗尽的任务额度。

## 查看和处理任务

总览的 AI 中控显示运行状态和计数，任务队列显示逐篇阶段、等待、失败和跳转入口。
可暂停、取消或从断点继续任务。批量操作读取当前版本，再逐份提交，部分失败会单独显示。
已保存成功的步骤保留；人工暂缓、拒绝或修改的资料不会被自动覆盖。

基础发布后，人工修改先成为草稿。确认时检查整篇文档的当前条目修订。
查询继续使用上次确认版本；拒收、撤回和隐私变化仍立即限制可见范围。

## 旧任务和升级

v0.5.0 新任务使用 `confirmed-content-v1`。旧任务保留历史记录和取消操作，
不能再恢复旧的“召回、逐对联系、最后发布”顺序。需要处理的资料应明确新建当前流程任务。
历史预算和已保存回答保留，不自动续额。

已移除“导入后自动分流”、独立条目评分路由及相应页面/API。
来源接收只负责保存原文与待审核记录。新流程由统一文档用例负责。

升级前备份数据库和原文，执行全部迁移与运行角色授权，再启动应用。
详细步骤见[运行维护](production-operations.md)和[v0.5.0](releases/v0.5.0.md)。

## 接口

- `POST /api/v1/ingestion/commands`：策略读取/保存、接收审核、接收控制和自动处理队列。
- `POST /api/v1/ai-tasks/commands`：文档任务、批量控制、发布确认及主题操作。
- MCP 使用相同应用用例，所有者操作与外部 Agent 授权分别校验。

完整操作列表见[Agent 接口](agent-interface.md)。来源、策略、主题、报告、任务和费用记录都保存在个人工作区。
