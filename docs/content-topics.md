# 主题与重点联系

主题整理在确认入库之后独立运行。
归组失败时，已经确认的正文继续可查。

## 使用入口

在文档阅读中选中条目，打开“主题与联系”。面板分为三项：

- **主题**：查看主题范围、概述、成员、加入原因及正文依据。可查看全部主题。
- **相似候选**：查找值得一起阅读的条目，核对后再让 AI 归组。
- **归组任务**：查看等待原因、尝试次数和费用，继续允许恢复的任务或取消任务。

候选查询无需模型。默认一组最多 8 条，包含当前条目，可调整为 1–12 条；
可限定候选的发布日期和是否比较不同适用条件。默认不生成具体联系，可将上限设为 1–4 条。
没有合适主题或具体联系也是正常结果。

让 AI 归组需要已有的外部批次预算。面板显示当前预算编号、余额和暂停状态；
填写的编号须与运行实例配置的预算一致。此入口只使用剩余额度，不创建预算或解除暂停。
调用遵守 AI 总控、价格时段和模型并发设置。预算未配置、编号不符、额度不足或暂停时保持等待。

## 人工整理

可以手动创建主题、修改名称与范围，再把选中的条目加入主题。加入需要填写原因和正文原句。
成员可以固定或排除；AI 保留这些决定。每次修改检查主题和正文版本。
正文更新后，旧依据保留并提示核对；不能用旧版本依据覆盖新正文。

“手动建立或修改联系”可选择两个成员，分别填写正文依据和联系说明。
联系分为支持、反驳、延续、替代；同一对成员再次保存会更新该联系。
可屏蔽或恢复联系。人工联系、屏蔽和已有旧系统人工决定优先于模型输出。
外部 Agent 可以使用已授权的关系写入接口，但不能覆盖人工决定。

## 候选与主题的区别

候选由已确认的公开正文和有效标注计算，拒收、撤回、私密和未发布草稿不参与。
确认的同义词使用共同身份；相关词保持各自身份。同名词不按拼写合并。
共现只统计同一阅读条目中同时出现的标注。合集中的不同条目不相互增加共现次数。
同一发布者对一个词对最多贡献一次；完全相同正文去重，高频词和宽泛领域词降低权重。
样本不足会说明。AI 已生成的主题与联系不用于增加共现样本。

召回只计算当前条目的邻近词，结合正文词语匹配排序；每组限制同源、同文档及重复正文的占比。
候选使用标注和正文检索计算，模型只处理选定的候选组。
候选分数是阅读线索。只有经过检查的成员及其原文依据才进入主题。

一条内容可以属于多个主题。每个主题保存名称、范围、成员、加入原因、依据及版本。
概述注明本次输入所覆盖的成员版本。成员或正文变化、概述未覆盖全部成员时显示“概述待更新”。
每次只处理选定组及其相关主题，保留其他成员和人工决定。具体联系是可选结果，不用相似度替代事实关系。

## 后台执行与费用

相同正文版本、候选、规则和人工决定复用已有任务，已保存回答不会因为再次点击而重发。
一次归组按整组记账，不把费用重复计入每篇文档。无用量回执时保留预留费用并明确标记。
新任务冻结当前自动重试次数，只对连接类失败做有限重试。格式、证据或版本问题停下供检查。
取消后保留已完成的记账和在途回答，不再应用结果。恢复数据包后，活动任务转为暂停，等待所有者决定。
新确认文档登记归组待办。用户选择候选组并使用已有预算启动。

## HTTP、MCP 与存储

以下共享命令可由所有者 HTTP 和已授权 MCP 使用。所有读取都需要 `entries.search`、`relations.read`。

| 操作                 | 用途                                   |
| -------------------- | -------------------------------------- |
| `topics_list`        | 按条目或全部读取主题与任务状态         |
| `topics_preview`     | 只读计算候选及本组输入，不调用模型     |
| `topic_save`         | 创建或修改主题名称和范围               |
| `topic_member_set`   | 固定或排除成员，携带修订及原句         |
| `topic_relation_set` | 保存、屏蔽或恢复重点联系，携带两端依据 |

写入还需要所有者的 `relations.revise` 或 Agent 的 `agent.relations`；修改已有主题须提供 `expectedVersion`。
模型任务 `topic_job_start`、`topic_job_control` 仅开放给所有者 HTTP，使用
`/api/v1/ingestion/commands`。开始和继续还需 `models.use`，取消不需要模型权限。
命令结构以共享 Zod schema 与 MCP 工具 schema 为准，不从文本描述推断新权限。

迁移 `000042` 增加工作区隔离的主题／归组任务记录表。主题、成员、原句、模型输入、结果、使用记录均属于个人数据。
Processing Bundle v18 保存这些记录，并继续读取 v17 及更早的数据包。旧包升级为空的新表；
恢复保留人工决定及费用记录，排队和运行中的任务暂停，历史失败保持原终态。
规则模板和合成样本可进入 Git，实际资料与产物不进入仓库。

独立归组模块不改写旧文档任务的历史步骤。活动实例统一切换和旧路径清理分别留在 P7、P8。
程序可核对格式、引用、版本、权限与费用边界；主题是否有用、关系是否成立，仍需有限真实验收。
