## 使用方式

在“查询 → 搜索与显示设置 → 保存的查询”输入名称，选择“另存当前查询”。
每个工作区最多保存 20 项，名称最多 80 个 Unicode 标量。
可以打开、重命名、用当前条件与位置更新，或删除保存的查询；删除不会影响条目和来源。

打开会重新执行当前查询，保留文字模式、检索模式、字段、来源、类型、领域、自定义名称、时间、拆分方式和关联中心等既有条件。
只保存上次选中的 Entry 身份，不保存结果正文或分页游标。
该条目若不在新结果首页，会在“上次查看的位置”单独读取当前版本，不混入结果总数与排序。
条目退役、不可见或不存在时显示可继续的提示；关联中心或语义模式不可用时，可以清除中心或改用文字查询。

查询可以打开精确原文，或以选中条目进入图谱，再用“返回查询”恢复条件和选中位置。
这些页面间的临时上下文只保留在内存；刷新应用后需主动打开已保存查询。
查询包含隐私范围时，每次重新打开都要选择“按保存的隐私范围打开”或“仅公开范围打开”。
先前保存的范围不会自动授予披露权限。

## 实现与数据边界

外部 review preferences 新增独立 `entrySavedQueries` v1 集合，以集合 revision 校验写入。
现有工作区串行更新只替换此字段；标签、分类、联系、探索、订阅等兄弟偏好保持原值。
新个人数据包携带该字段，旧文件和旧包补为空 revision-zero 集合；恢复失败时连同其他偏好回滚。

| 入口                                 | 职责                                   |
| ------------------------------------ | -------------------------------------- |
| `GET /api/v1/entries/saved-queries`  | 读取当前工作区命名查询                 |
| `POST /api/v1/entries/saved-queries` | 以 expectedRevision 保存、重命名或删除 |
| `POST /api/v1/entries/query-context` | 按明确隐私范围读取一个当前 Entry       |

保存和普通搜索复用[同一个查询校验](../apps/server/src/modules/entries/information_entry_search_request.ts)。
[保存协议](../apps/server/src/modules/entries/information_entry_saved_queries.ts)拒绝 cursor、结果正文、AI 答案及任意附加 payload。
[查询页](../apps/web/src/workspaces/information_entry_query_workspace.tsx)不自动记录检索历史或更新保存项；比较与 AI 答案仍是当前范围下的会话数据。
没有新增迁移、依赖、数据库表、Provider、数据包 section、公开分享地址或内容写权限。
