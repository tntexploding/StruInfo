# StruInfo v0.4.0

2026-10-19

本版将订阅补收、来源反馈、AI 执行设置和已验收的新界面整理为一个可升级版本。

## 使用变化

- 文档入口可通过 RSS、站点地图和公开目录查找往期资料，按来源和时间选择、限制数量后加入待审核队列。
- 来源介绍支持可编辑的 AI 草稿；人工接受/拒绝可作为后续审核参考。来源持续出现问题时，在总览提示你决定保留、重审或关闭。
- AI 并发和断点重试次数可配置。文档任务保留原文、已完成步骤、预算、人工决定和价格时段。
- 完善合集切点、附属内容处理、小条目标签批次和带证据的联系判断。无联系是允许的结果；尚未验收的语义复核实验不作为新任务默认行为。
- 总览、文档入口、工作台、数据阅览、报告和设置使用统一主题。正文保持实色，交互控件使用玻璃和柔光；流程动效只响应实际完成和统计增量。
- README 和首次安装指南改为面向使用；贡献指南补充代码目录和验证入口。

## 清理与修复

删除 11 个不可从应用入口到达的旧页面/组件，以及对应的旧界面测试，保留现用编辑逻辑和历史兼容接口。修复生产依赖和构建工具的安全告警，运行镜像改用固定版本的官方 Node Alpine 基础层，移除已下架的 Debian 包版本安装步骤。许可证、第三方声明和 SBOM 随实际依赖更新。修复数据库演练中写死 Windows 路径分隔符的问题，Linux 和 Windows 使用相同的临时目录清理边界。

本次审计覆盖生产模块引用、任务恢复与预算、人工决定、入库可见性、历史补收、版本迁移与恢复、前端和制品边界。使用合成数据验证；没有调用真实模型、处理剩余资料或更改私人实例策略。

## 从 v0.3.0 升级

1. 停止应用写入，用当前版本创建并完整校验外部备份，保留旧镜像。
2. 构建 v0.4.0 镜像，保留现有工作区 ID、数据库、数据目录和外部配置。
3. 执行 `migrate`、`prepare-queue`，再应用 `deploy/postgresql/apply-runtime-grants.sql`。
4. 执行 preflight，启动单个 `all` 应用实例，检查健康、文档、任务和查询。
5. 确认升级结果后保留一份新备份。不要自动扩大订阅范围、AI 许可或重试额度。

本版包含 `000039_add_ai_split_source_ranges.sql`：为 AI 拆分记录增加原文范围，旧整段提案保持可读。处理数据包升级为 v15，同时保留旧版本读取和补齐逻辑。迁移是前向的；回退应使用旧镜像和迁移前已验证的备份恢复到空目标，不能直接覆盖现有数据库。

详细命令见[运行维护手册](../production-operations.md)。发布源码不会自动升级已经运行的实例。

## 验证与范围

本地通过 1,888 项单元测试、4 项集成测试、71 项浏览器场景、构建和制品检查、隔离 PostgreSQL 演练，以及新运行镜像的安装与启动检查。完整依赖审计和生产依赖审计均未发现已知漏洞。CI 重复运行质量检查、浏览器与数据库演练，并检查运行镜像兼容性和 HIGH/CRITICAL 漏洞。发布结果见本版提交对应的 [Quality](https://github.com/tntexploding/StruInfo/actions/workflows/quality.yml) 和 [Maintenance security](https://github.com/tntexploding/StruInfo/actions/workflows/maintenance-security.yml)。
