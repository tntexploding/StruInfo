# StruInfo v0.3.0

- 日期：2026-09-20
- 范围：文档中心工作区、统一 AI 处理及可恢复任务的累计源码更新

## 使用变化

文档入口负责订阅、上传和接收决定；工作台围绕全文处理结构、标签、联系与翻译；
数据阅览集中查询、关系图与引用问答；报告管理选材、生成队列与历史。
总览显示 AI 总控、当前状态和逐篇任务进度，设置集中管理偏好与模型接入。

人工接受和 AI 审核通过都可进入完整整理任务。任务按审核、结构、标签、联系、入库推进，
只在完成或显式人工确认后进入查询、RAG、图谱和新报告选材。人工修改保留为草稿，
外部 Agent 通过同一版本检查确认，不能绕过授权直接写入。

连贯长文保留上下文，独立合集才分组；支持最多 64 条目与 128 个证据输入单元。
任务按实际拆分结果预留后续调用额度，超限停止而不截断或自动追加预算。
已确认标签别名参与检索与 RAG 定位，原标签与原文保留。

队列支持最多 32 篇一批的断点继续、有限重启和取消。只有耗尽的失败任务可以显式开启
新一轮同额度尝试；历史调用、完成步骤与人工修改保留。已拒收的静止历史任务不再计入
当前批量取消。AI 许可、串行调度和价格窗口统一应用于内置调用。

日报、周报、月报与专题报告可使用 AI 或确定性资料摘录；支持 Markdown 导出与本机
打印保存 PDF。尚未接入消息推送渠道，也不默认创建周期报告。

## 升级与兼容

1. 停写并创建、校验外部完整备份，再升级应用。
2. 从 v0.2.0 升级时，按现有运维流程执行前向迁移至 000038、queue 准备、runtime grant
   和 preflight。已到该迁移的实例不增加新迁移。
3. 启动后核对文档入口、工作台、已入库查询、任务队列和已有报告。
4. 部署不会自动重启历史失败任务、扩大订阅范围或启用无人值守。恢复数据包仍需显式继续。

旧数据包继续可读；新增接收与发布元数据使用既有 JSON 边界。未参与新流程的历史材料
保持原行为，编辑或重处理后纳入确认规则。回退应使用升级前备份和对应程序，不能在
非空正式数据库上倒退迁移。完整操作见[运维手册](../production-operations.md)。

修正了英文正文中普通 `bearer of …` 短语导致完整备份失败的问题；授权头、独立 Bearer
值与密钥检查继续生效。历史空版本清理属于所有者明确选择的单次维护，不提供自动删除。

## 发布边界

保持私人单用户、all 单实例、PostgreSQL 18 和外部数据根。原文、订阅配置、密钥、
浏览器截图、备份及运行记录不进入 Git 或应用镜像。内置模型只接收符合当前授权的公开材料；
MCP 的读取、接收、处理、采集与结构权限仍独立配置。没有模型也能使用人工与确定性流程。
