# 标签与公共词表

## 处理流程

文档审核通过后，按来源方案拆分。AI 对每个条目生成一套标签：
内容类型、领域、对象、议题、用途、条件。没有依据的类别留空。
标签保留名称、含义、类别和原文引用。原文中的明确观点随同保存。
同一批条目共用一次请求中的词表，条目分别返回结果。

结果通过引用范围、正文版本和身份检查后保存。人工修改优先。
AI 文档任务按现有流程确认发布；人工修改保存草稿后，由人确认。
搜索、问答、报告和主题归组读取确认版本。

## 公共词表

词表由个人配置和当前公开条目使用的标签组成。
已保存标签的名称、含义和类别相同时，复用同一个身份。
同名不同义分别保存。模型优先使用请求中提供的已有词条。
人工确认的别名和同义关系参与查询；相关词不作为同义词。

自动生成的词条从标签记录读取，不为每篇文章重写个人配置。
模型按当前条目内容选择词条。一批最多传入 128 个，词表上下文上限为 24,000 个 Unicode 字符。
私密条目和正文已变化的旧标签不进入公开词表。
同义关系由人确认，不增加一次自动归并调用。

## 阅读与编辑

文档标签由条目标签汇总。阅读页按类别显示，编辑窗口逐条修改。
每个新标签都需要当前条目的原文依据。修改正文后，原标签标为待核对，停止参与标签匹配。
阅读状态独立修改，保留已有标签、原文依据和人工决定。

数据库按类别、词条、文字或阅读状态筛选。聚合保存这些条件和条目引用。
主题候选使用共同标签和标签共现关系。类型标签不参与候选匹配。
相同正文、同篇条目和私密内容排除。同一来源限制候选数量。
AI 在候选范围内核对正文，给出主题与有依据的联系。没有候选时不调用模型。
文档发布后自动创建归组任务，沿用原文档任务的预算、许可、价格时段和并发设置。
人工单独确认、旧发布记录没有绑定预算时，保留待处理状态，可通过主题任务入口指定预算。
暂停与失败保留记录。已返回的结果先保存，恢复时继续应用。

设置页管理同一套类别、词条、别名和关系。
个人词表、人工设置及标签记录随个人数据包备份。

## 接口与兼容

| 接口                         | 用途                         |
| ---------------------------- | ---------------------------- |
| `annotation_vocabulary`      | 读取公共词表                 |
| `entry_annotations_read`     | 读取条目标签及词表           |
| `entry_annotations_save`     | 按条目修订和词表修订保存标签 |
| `annotation_vocabulary_save` | 所有者保存词表配置           |

内置 AI、网页和外部助手共用上述标签结构。
文档级标签写入与聚合写入接口已移除。文档汇总在读取时计算。
普通关键词、类型和领域不再作为第二套生成结果。

历史标签可用 `tools/migrate_legacy_tags.ts` 一次性迁移。执行前停写并备份数据库和偏好。
类型和领域映射到对应类别。旧关键词保留名称，进入“未分类”；该类别不用于新模型生成。
迁移记录保留原标签来源，标为待补全，不补写词义和原文依据。原文、编号和发布修订保持不变。
迁移同时更新确认版本和文字索引，不调用模型。旧快捷词和别名进入统一词表，自动关键词设置移除。
旧数据包和历史提案保留读取能力；恢复旧库后可执行同一迁移。
旧批量入库、规则补标签、类型学习和评分分流实现已移除。
含文档级人工标签或已废弃条目结构的库，需先核对映射；迁移工具会停止处理。
`preferences/review` 和助手的 `review_settings_read/save` 已移除。
推荐权重使用 `preferences/recommendations` 读取，沿用各自的保存接口。
新提案只保存结构化标签载荷。迁移 `000044` 允许新提案省略旧类型字段。
许可、隐私、价格时段、并发和预算仍由原有控制负责。

## 主要消耗

标签生成读取条目正文，按当前批量设置请求模型。公共词表从已有标签读取，不另调模型。
候选匹配由程序完成，使用标签及共现统计，不做全文词语扫描。
主题判断仍需把候选正文交给模型。候选越长、数量越多，输入费用越高。
当前按条目建立主题任务，候选正文可能重复进入不同任务。这是剩余的主要调用成本。
候选标签统计仍按任务计算。资料增长后，这部分数据库读取与计算也会增加。
