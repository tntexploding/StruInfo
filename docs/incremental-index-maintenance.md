## 用户入口与行为

在“查询 → 搜索索引”选择“刷新变化项”。每批最多处理 32 个公开当前 Entry 或退役投影。
页面显示真实已收录、待刷新、过期数量和本批结果；可选择“本批后暂停”，完成后再继续。
离开页面会停止后续请求，在途批次仍可完成；重新打开后需显式刷新，服务根据数据库中的投影继续剩余工作。

新增或修订的条目只重建自己的词项。当前模型下有界标题、正文和标签输入没有变化时，
复用原向量；例如只改评分不需要重新生成向量。Provider 失败时保留本地词项和已完成部分，
并显示重试入口，普通文字查询继续可用。没有模型配置时，刷新完成本地词项即结束。

“完整重建与修复”是次要入口，保留索引版本、分词版本和词项数。
它可以修复任意派生内容损坏；配置了模型时会重新生成全部公开向量，界面明确提示调用成本。

## 实现边界

- [增量核心](../apps/server/src/modules/entries/information_entry_search_index_refresh.ts)只读取数据库选中的有限 Entry 集合，复用输入摘要和相容向量。
- [PostgreSQL 仓储](../apps/server/src/platform/database/postgresql/postgres_information_entry_search_index_repository.ts)按 revision、tokenizer 和模型元数据选项；每批在 workspace lock 下核对精确当前 revision、结构与公开范围，再原子更新词项和投影。生成期间变更的结果不标为有效，私密/退役投影按有限预算清理。
- 已提交投影就是检查点。没有新迁移、ProcessingRun、自动调度、进度文件、依赖或个人数据包部分；恢复后的空派生索引使用相同路径重新构建。
- 新端口为 `POST /api/v1/entries/search/index/refresh`，只接受可选整数 `limit`（1–32，默认 32）。不接受模型覆盖或隐私参数。同一 API 服务实例的刷新与完整重建串行，在途冲突返回 409。
- [Web 面板](../apps/web/src/workspaces/information_entry_search_index_panel.tsx)只在用户启动后连续请求，使用请求代次拒绝迟到状态，页面卸载后不启动下一批。
- 元数据选项仍需要数据库扫描；“只装载变化项”不等于“只扫描变化行”。任意词项/向量内容损坏由完整修复处理，不在每个窗口遍历全库向量。
- 不承诺跨实例或网络结果不确定时的外部调用恰好一次。提交有版本保护，失败窗口可能重试 Provider；真实费用与召回质量未测量。

发现并修复一项 `PRODUCT_BLOCKER`：人工关系保存被拒绝后，原图谱仍显示；
此时接受已有 AI 联系提案虽然成功保存，旧请求代次却会阻止图谱刷新。
人工写入现在绑定当前可见图谱的请求代次，只有新的读取或范围切换使该视图失效。
新增浏览器用例在修复前复现失败，修复后通过；跨隐私范围的迟到读取、人工写入与 AI 回调保护仍通过。

两次返回的完整结果及精确来源相等。刷新前后的空条件浏览均使用数据库分页，
累计 2 次分页读取，页面对象及游标相等。计数见 smoke 报告的 `incrementalIndex.queryIntegration`。
