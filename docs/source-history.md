# 往期补收

在源管理打开“补收往期”。
选择来源、发布日期范围和每个来源的数量上限。
先查询目录，再预览正文并选择资料，最后加入待审核队列。

查询支持 RSS/Atom、同站点 Sitemap、公开归档页，以及已识别站点的分页目录。
可填写当前来源的公开归档地址。
归档识别支持文章卡片、卡片日期、数字文章地址和 HTML 模板内的目录。访问验证页报告读取受限。
不同来源的历史覆盖范围按其公开目录决定。

## 操作

开始查询后，后台逐页读取各来源目录。关闭页面后可以继续。来源、日期和每个来源的数量上限随本批保存。查询结束后可预览原文，按页选取或全选，再点击**加入待审核队列**。提交时固定所选范围。

在批次列表查看新增、已存在、失败和待处理数量。展开**逐篇记录**可查看接收与审核结果、文档任务进度和已发布条目数。失败项显示原因，可单独重试。遇到网站限流，停止读取该来源，稍后手动重试。

可以暂停和继续。服务重启后从已保存的位置继续原先运行的批次，暂停的批次保留暂停状态。每个工作区最多同时保留 8 个未完成批次。目录、选择和逐篇结果保存在工作区数据目录的 `source-history/<workspaceId>`。实时订阅另存自己的游标。

网页和命令行共用批次编号、选目、进度和暂停状态。相同选目和日期范围复用已有批次。默认补收到待审核。点击**AI 审核并整理本批**后，服务端按现有预算、价格时段与并发设置提交本批新增文档。每篇使用所属来源的条目上限。已有资料与人工决定保留。

命令行 `tools/historical_batch.ts` 的 `prepare` 生成选目清单。`capture --execute` 提交补收，`run --execute` 提交补收及 AI 处理。用 `--origin` 指定本地实例，通过 `--manifest` 和 `--batch` 选择清单，或用 `--session` 指定网页中的批次编号。`status`、`pause` 和 `resume` 操作同一条服务端记录。`--retry-failed` 可重试采集失败项或未提交的文档任务。

AI 处理使用工作区已配置的批次预算。清单预算编号为 `清单ID-批号`；从网页开始的批次在首次提交时绑定所选预算。旧清单保留原先授权的较低任务上限。旧进度文件用于接续已有资料和任务，新进度统一由服务端保存。

补收沿用接收入口的来源、日期、去重和原文存储。受限正文显示为失败。新增资料进入待审核。后续文档任务遵守接收策略、模型许可、价格时段和预算。

同一公开来源先补收、后订阅时，核对同一地址的最近记录。网页正文一致，或 RSS 标题一致且全部正文段落已连续保存在补收原文中，沿用已有文档与审核决定。正文有改动时保留新的接收记录。
