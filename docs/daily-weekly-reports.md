# 日报与周报

启用「设置 → AI 接入 → DeepSeek 峰谷价格」后，高峰时段提交的生成请求进入等待，不消耗模型预算；低价时段自动继续生成。已有在途请求允许完成，下一条摘要开始前再次检查。此功能只恢复已经提交的生成任务，不定时创建新日报/周报；取消仍然有效。

ADR 0081 增加独立的「报告」工作区。日报与周报从当前工作区内**已放行、已入库的公开材料**选材，生成有出处的中文草稿，支持人工核对和 Markdown 导出。报告内容与来源正文分别保存，不修改原文、条目、标签或关系。

## 使用

1. 打开「报告」，选择日报或周报，以及报告日期。周报覆盖所选日期所在的周一至周日。
2. 默认按接收日期选材。也可选择发布日期；没有发布日期的材料会被排除。日期使用界面显示的 IANA 时区，不依赖服务器所在时区。
3. 点击表单内的「预览材料」。按需要排除条目，再点击旁边的「新建日报」或「新建周报」创建草稿。这两步不会调用模型。
4. 点击「生成草稿」。系统先识别并排序独立事件，再按条数上限选择摘要；未入选事件保留在「其他阅读」。选择「手动编写」也可以完成没有配置模型的工作区。
5. 报告默认显示阅读正文，历史列表从顶部「报告历史」展开。点击出处回到资料库，再返回「报告」。标题旁的「核对与编辑」打开右侧工作台，可修正段落、回看来源、取消本期不需要的条目，最后保存草稿或确认已核对。关闭工作台或按 Escape 只收起，当前页面中的编辑保留；刷新浏览器前请保存。保存冲突时保留修改并提示重新核对最新版本。
6. 导出 Markdown。文件包含报告状态、日期依据、摘要出处及条目版本。未核对的导出会明确标为草稿。

报告按需生成；创建报告不会设置定时任务或向其他应用发送内容。自动接收和入库仍受原有策略控制。日报不要求每天都有内容，周报也不要求凑满条数。

## 选材与证据

- 收件审核 `admitted` 是选材前提。暂缓、拒收、待审核、隐私材料，以及尚未形成条目的文档均不进入报告。
- 网页正文使用其接收审核记录的原始快照日期，不把后来提取全文的时间冒充接收时间。
- 同一时间窗口、同一规范来源地址的多次捕获，采用最新捕获；这一捕获内独立拆分的条目仍保留。完全相同的正文另外去重。窗口之外的新捕获不会抹去历史窗口的候选。
- 可按话题文字、来源名称或域名筛选。排序先考虑话题命中和已有显式评分，再按日期与稳定标识排序；目前不是语义检索。最多展示 40 条候选，人工勾选形成明确清单，不会自动补入未勾选材料。
- AI 选题接收标题、标签和有界预览；摘要接收所选组的完整条目正文。超过输入边界会停止并提示，不能截去正文后假装完成全文摘要。
- 同一具体事件、公告或事实主张的重复报道可以合并；不同产品更新或研究结论分别成条，同一出版机构或技术领域本身不构成合并理由。新 AI 摘要按自然阅读顺序返回 1–4 段，简单消息可只有一段，必要限制紧随相关结论。段落角色保留为内部数据，界面与 Markdown 导出不显示固定三段标题；每段最多 140 字符；超限会报告失败而不裁去文字，人工编辑仍可写得更详细。每段至少引用一个本组出处，未知或重复编号会被拒绝。
- 新报告分别保存发布日期和原始接收日期。早于本期的文章标为“补充阅读”，推定日期明确标示，没有发布日期时显示未知；统计年份、事件时间、预测时间与接收时间分别记录。旧稿不追补日期或重写摘要。
- 报告保存选材时的条目版本和快照标识。材料后来改变时显示过期提示，并停止生成、核对和导出；重新选材生成新报告可保留前后对照。材料变成隐私、被拒收或移除后，旧报告也停止展示和导出。
- 引用校验检查出处编号。摘要是否准确、是否忠于原文，由人工核对。
- 每条摘要底部集中列出引用，同一来源只显示一次。只引用一份材料时，段落不重复标号；引用多份材料时保留各段的简短来源编号。Markdown 导出遵循相同规则，原有逐段引用记录保持不变。

## 运行、额度与恢复

默认最多 6 条报告内容、累计 12 次模型调用；上限分别为 8 条、20 次。一次选题规划及每条摘要各计一次调用，失败和续跑也累计在同一报告内。每次网络调用前先持久记录已消费额度。

选题模型不接收本期条数上限，最多 40 条冻结候选必须完整、不重复地归入事件组。应用随后按推荐顺序取至上限，其余组保留在“其他阅读”，不会被丢弃。遗漏候选或伪造出处时停止生成，已消耗的调用计入原额度。

生成逐步保存已完成内容，失败后可「继续生成」，只处理未完成部分。报告为 `queued` 或 `running`、但当前没有执行器时，通常显示中断并要求显式继续。ADR 0082 仅让价格等待在普通重启后继续等待并于低价时段恢复；数据包恢复、其他中断与失败仍须显式继续。取消后在途响应不能覆盖取消状态；已发出的模型请求可能仍产生一次费用。

模型沿用现有配置与 Responses 适配器，没有新增密钥字段、Provider 或依赖。没有配置模型时，选材、人工编辑与导出仍可使用。人工修改另存于报告条目中，原始 AI 草稿仍保留；正常保存会回到待核对状态，只有明确操作才能标记已核对。

## 接口与持久化

本机所有者使用 `POST /api/v1/reports/commands`，请求为 `{operation, input}`。支持：

| 操作                                | 输入                                  |
| ----------------------------------- | ------------------------------------- |
| `report_preview`                    | 报告条件                              |
| `reports_list`                      | 空对象，返回最近 100 份当前可见报告   |
| `report_read` / `report_export`     | `reportId`                            |
| `report_create`                     | `requestKey`、报告条件                |
| `report_generate` / `report_cancel` | `reportId`、`expectedVersion`         |
| `report_edit`                       | `reportId`、`expectedVersion`、`edit` |

报告条件包含 `kind`（`daily` / `weekly`）、`date`、`timeZone`，以及可选的 `timeField`、`topics`、`sources`、`excludedEntryIds`、`selectedEntryIds`、`maxItems`、`maxModelCalls`。`selectedEntryIds` 明确限制候选清单；省略时按条件选取前 40 条。创建的幂等键绑定工作区、所有者与请求，不会重跑模型。

外部 Agent / stdio MCP 增加 `report_preview`、`reports_list`、`report_read`、`report_export` 四个只读工具。读取报告要求现有公开条目与处理记录读取权限；报告写入、调用模型和核对均留在本机所有者入口。**既有 Agent grants 不变**。MCP 导出只返回文件名和 Markdown，不向外部服务发送报告。

迁移 `000038` 增加 `processing_report`。报告以闭合类型保存选材、摘要、状态、版本和累计调用额度，不保存密钥、原始 Provider 响应或错误正文。Processing Bundle v14 携带报告历史，v1–v13 恢复为空报告历史；在途报告恢复后等待显式继续。所有实际材料和报告保存在外部数据库/数据包，不能进入仓库或测试样本。

本轮不包含定时出刊、邮件/聊天推送、月报、跨工作区聚合、外部 Agent 报告写入或对历史语料的批量重新审核。
