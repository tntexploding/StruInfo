# 来源拆分方案

在**源管理 → AI 方案 → 模板与匹配**配置来源。在文档阅读中可以单独指定本篇方案。
同一来源可以启用多个格式模板。模板保存处理方法、结构条件和版本。
原文、人工修改、确认发布与后台主题归组沿用现有流程。

## 取样与建立

1. 接收少量完整文档，点击**按格式取样**。按时间分散扫描，再按结构分组。
2. 每种格式分别取样。数量不足的组继续等待资料。
3. 按格式生成方案。系统取同组样本，用最后一篇独立试读。AI 生成时只看训练样本。
4. 核对草稿的方法与试读结果，再确认启用。格式相同且通过旧样本检查的修订可替代旧版。新格式或与旧样本不兼容的方案另存为模板，可与原模板同时启用。

取样引用现有文档，保存文档 ID、格式、分数和试读结果。任务携带模板版本与方法，不携带训练样本正文。
模板只描述边界、编号、标题和上下文的处理方式。主题、实体、结论与固定标签不属于拆分模板。
AI 建议需要核对，尤其是合集与连贯文章的区别。

## 执行方式

| 方式        | 处理                                                 |
| ----------- | ---------------------------------------------------- |
| 规则拆分    | 整篇保留、独立编号、同级标题或带说明的链接目录       |
| AI 判断切点 | 使用已选模板的方法说明，通过现有文档任务生成实际切点 |

连贯教程的章节、同一过程的步骤保持连续。合集中的独立文章和工具分别处理。
规则支持指定标题层级、条目数量、正文长度、附录标题及编号重置。
前言附到首条，附录随相邻正文保存。代码块与原文保留。

规则试读显示 Unicode 字符范围及完整覆盖。AI 模板试读检查输入与结构匹配；实际切点由文档任务产生。
来源模板启用所需正常样本数取自来源设置，并须包含变体或独立检查样本。保留的试读须符合预期。
仅本篇模板需要一份正常试读。每个模板最多保留 16 份不同文档的试读记录。

## 匹配与复核

匹配使用标题层级、结构段数量、编号比例、链接比例。取样学习数值范围，人工可修改条件、权重及单模板放行线。
分数为 0–100，衡量结构相似程度。内容独立性、标题质量和附属内容归属需要另行检查。

本篇模板优先。来源模板按得分排序。最高合格候选达到放行线，且与次候选分差足够时使用。
低分、候选接近或边界检查失败时，按模板设置交给 AI 单独评价或人工核对。
低分候选的方法不会作为已匹配规则强加给 AI。没有模板时使用现有 AI 拆分流程。

按来源、模板版本及格式记录匹配结果。在近期记录可标记切点、标题或上下文问题。结构异常与人工标记按文档去重，分别展示。观察窗口满且问题占比达到设置值时，总览提示复核。可从提示进入模板面板，用异常样本生成草稿。所有者核对后启用或调整放行线。

已有稳定切点时，可用已确认条目提取规则。训练样本和留出样本的原文范围、顺序与标题须全部吻合。规则通过后仍须确认启用。待人工复核的拆分任务可按新模板继续，也可只将该篇交给 AI。任务保留原先的选择记录。

### 来源设置

| 设置         | 初始值 | 范围                  |
| ------------ | ------ | --------------------- |
| 每种格式取样 | 3      | 2–12 篇               |
| 单源扫描上限 | 24     | 2–96 篇，至少覆盖一组 |
| 模板放行线   | 80     | 1–100                 |
| 候选最低分差 | 10     | 1–100                 |
| 观察最近篇数 | 20     | 5–100                 |
| 复核问题占比 | 30%    | 1%–100%               |

这些值保存在来源的 `processingProfile.splitRouting`，可在模板面板修改。
拆分补充要求只作用于 AI 拆分；填写后仍按模板匹配选择执行方式。
标签与联系提示继续用于对应阶段。新任务冻结创建时的配置，已有任务保留原版本。

## 接口与存储

所有者 HTTP 入口为 `/api/v1/ingestion/commands`，系统助手复用这些用例。

| 命令                                                                | 用途                             |
| ------------------------------------------------------------------- | -------------------------------- |
| `split_source_read`                                                 | 来源模板、匹配设置和复核统计     |
| `split_source_sample`                                               | 按格式返回现有文档引用           |
| `split_source_suggest`                                              | 从一组公开样本生成草稿           |
| `split_source_feedback`                                             | 标记当前文章的切点、标题或上下文 |
| `split_source_calibrate`                                            | 按格式生成、试读并保存待确认方案 |
| `split_source_status`                                               | 汇总需要复核的来源               |
| `split_recipe_save` / `split_recipe_trial` / `split_recipe_control` | 保存、批量试读、启停与替代       |
| `split_recipe_suggest`                                              | 当前文档的 AI 建议               |

`split_recipes_read`、`split_recipe_preview`、`split_recipe_apply` 继续供 HTTP 与 MCP 的文档操作使用。
写操作携带目录 `expectedRevision`。匹配统计不改变模板目录修订。AI 模板通过文档任务执行，不能直接作为规则应用。

方案与匹配记录保存在仓库外 `review-preferences.sourceSplitRecipes`，随个人数据包备份恢复。
旧配置缺少新增字段时沿用默认值。仓库保存通用代码与合成测试。
模型建议只接受公开原文，使用现有许可、价格和调用限制。后续任务沿用原预算、并发和重试设置。

在**源管理 → AI 设置 → 每篇最多条目**为每个来源设置 1–64 条。未设置的来源使用引擎容量 64 条。实时接收、往期补收、人工接受后的整理与助手共用此配置。新任务创建时固定上限。单次明确指定的更低上限继续有效。没有来源的手动文档默认 12 条。

模板里的最多条目用于该格式的规则检查。超过本篇上限时停止写入并保留原文。规则容量还包括 32 万 Unicode 字符及 32,000 行。
目录最多 128 个模板。超限保留原文并提示核对。规则只生成草稿，确认后进入查询。
