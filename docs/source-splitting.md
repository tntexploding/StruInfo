# 来源拆分方案

P3 为来源和文章格式保存固定拆分方案。操作入口在**文档阅读 → 编辑 → 拆分方案**。
来源已有稳定格式时，新文档任务可以按规则计算切点，省去模型拆分请求。
原文、标签、人工修改和确认入库规则继续保留。

## 选择方式

| 方式             | 适用内容                         | 处理结果                               |
| ---------------- | -------------------------------- | -------------------------------------- |
| 整篇保留         | 连贯文章、教程、短技术说明、快讯 | 全文为一个阅读条目                     |
| 独立编号条目     | 连续编号的周刊或合集             | 每个独立条目一段；编号重置或跳号时暂停 |
| 同级标题条目     | 每个同级标题对应独立文章的合集   | 按指定标题层级分段                     |
| 带说明的链接目录 | 有独立说明的资源介绍合集         | 按标题或编号开头的链接分段             |

教程中的章节和操作步骤通常依赖上下文，应选择整篇保留。
普通正文链接、代码块中的编号和纯链接清单不会自动成为目录条目。
前言附到第一条；配置的附录标题及其内容附到前一条。原文不删减。
规则使用 Unicode 字符范围，预览显示每个条目的标题、起止位置和完整覆盖结果。

## 建立与启用

1. 选择适用范围：当前来源，或仅这篇文档。手动上传且无来源绑定时只适用于本篇。
2. 选择模板，设置标题条件、标题层级、条目数量、最少正文长度和附录标题。
3. 点击**预览切点**。预览不写条目。可选的 **AI 建议方案**只生成可编辑草稿。
4. 保存草稿，在不同文档上**记录本篇试读**。标明常见格式、变体或例外，以及预期正常拆分或暂停。
5. 核对结果并填写说明，再启用。来源方案需要至少两份不同的正常样本，并包含变体或例外样本；本篇方案需要一次正常试读。所有保留的试读都须符合预期。

试读记录保存实际程序结果。人工仍需检查各段能否独立阅读、附录归属是否合适。
规则通过范围校验并不表示内容已经完成语义审核。

已启用的方案通过**复制为修订草稿**修改。新方案完成试读并启用后，旧方案才标为已替代。
暂停、修改或替代不会更改已经创建任务所保存的方案。
每个方案保留最近 16 份不同文档的试读记录；参数修改后需重新试读。

## 自动处理与手动应用

新文档任务保存创建时的方案版本和规则执行器版本。匹配时，本篇例外优先，
其次为标题条件更具体的来源方案；同等条件存在多个方案时暂停。
没有来源方案时沿用现有模型拆分流程。

规则命中且校验通过后直接生成条目，不记为模型请求。
写入前仍检查本任务条目上限和后续标签、召回、联系的最低调用额度。
标签及后续处理继续受许可、价格、并发和预算限制。
失败恢复保留已生成结果和原方案；已有人工结构或修改草稿不会被规则覆盖。

格式不符时默认暂停，原因显示在任务中。可以在方案里明确选择使用任务原有额度
交给 AI 拆分。不会自动增加预算、截断内容或改写方案。
要调整已冻结的任务方案，应先取消旧任务，核对新方案后由用户另行启动任务。

**应用到当前文档**只用于已接受、未暂缓且尚无条目的文档。该操作生成待确认内容，
点击**确认入库**后才进入查询。已有条目使用原有的**修改分段**功能。
基础发布与后台归组继续分开；P3 不启动 P5 的主题处理器。

## 接口与个人配置

HTTP 和 MCP 共用以下用例：

| 命令                   | 权限                             | 用途                             |
| ---------------------- | -------------------------------- | -------------------------------- |
| `split_recipes_read`   | `documents.read`                 | 读取当前文档可用方案             |
| `split_recipe_preview` | `documents.read`                 | 预览给定声明式方案               |
| `split_recipe_apply`   | `documents.read` + `agent.split` | 应用已启用方案，随后仍需确认发布 |

保存、试读、启停和模型建议通过所有者 HTTP 入口 `/api/v1/ingestion/commands` 操作，
命令分别为 `split_recipe_save`、`split_recipe_trial`、`split_recipe_control` 和 `split_recipe_suggest`。
写操作携带目录 `expectedRevision`；旧版本冲突会拒绝本次写入。
外部 Agent 不能调整自动方案、启用规则或调用建议接口来扩大自己的权限。

个人方案保存在外部 `review-preferences` 的 `sourceSplitRecipes` 中，随个人数据包备份恢复。
仓库只包含通用模板、校验和合成样例。旧配置缺少此字段时视为空目录。
模型建议仅接受公开原文，使用现有模型和调用门禁；不会接收私人资料或执行生成的脚本。

当前规则上限为每篇 64 个条目、32 万 Unicode 字符和 32,000 行；任务可设置更低上限。
目录最多 128 个方案。超限时保留原文并提示核对。
这些是本轮实现边界，不表示所有来源格式都已适配。

## 来源级 AI 处理提示

源管理可编辑拆分、标签、联系的附加要求，每项最多 4,000 字符，并设置来源卡片颜色。
这些配置与来源一起存入个人偏好和备份包，不写入仓库。

填写拆分提示时，新文档任务使用有界 AI 拆分；留空时沿用已启用的规则方案。
“AI 填写拆分建议”使用现有建议接口，将建议放入可编辑草稿，保存后生效。
规则方案的预览、样本试读、启用与替换仍按原流程操作。

新建文档任务（含重新整理）保存一份当时的来源提示。执行时分别交给对应的拆分、标签和联系适配器。
并发任务的提示相互隔离；历史任务没有提示时保留原行为。提示不会放宽原文覆盖、证据、输出格式和隐私要求。
后台主题归组继续使用 P5 独立的证据规则与预算；来源提示不直接改写已有主题。
