## 修正与保留的行为

1. 保留空条件 Entry 浏览的数据库计数/分页、索引状态聚合、按端点读取联系的三个可选快路径。
   完整路径继续处理复杂条件；没有增加索引、迁移、依赖或搜索服务。
2. 图谱重新读取、换中心或切换隐私范围时，清除旧的创建关系候选并使旧请求失效。
   迟到的人工写入和 AI 接受回调不能以旧范围重新打开图谱；已提交的命令仍按原来的服务端权限和并发版本结算。
3. 来源面板从载入开始就接收键盘焦点；关闭和 Escape 会使在途读取失效。
   关闭后回到原按钮，失败后重试保留原焦点目标和片段选择。
   窄屏浮层有对话框语义、Tab 循环和背景 inert，桌面仍是可并排阅读的来源栏。
4. 图谱详情先展示条目，再给关系编辑与创建区域足够宽度；窄屏堆叠。
   连线说明可用 Escape 收起；图谱与关系列表都保留方向、自动/用户/AI 来源和双端原文入口。
5. 顶部状态栏可在 200% 字号下收缩，避免横向溢出。
   自动分流详情恢复完整运行编号，保证同前缀记录仍可区分。
6. 浏览器回归同步当前中文名称，增加有状态图谱、迟到请求、来源重试和键盘回归。

## 读取等价与合成测量

[现有 PostgreSQL 演练](../tools/m2_p0d_postgres.ts)现在调用
[候选读取回归](../tools/current_read_candidate.ts)，报告 schema 升为 `struinfo.m2-p0d-postgres-report.v3`。
它复用同一个一次性数据库，在原产品流程计数之后进行读取对照，不连接已有工作区。
报告把附加验证耗时列为 `readCandidateMilliseconds`；原流程的 persisted/productFlow 计数先记录，随后才扰动合成当前态。

smoke 使用 4 个 Snapshot、32 个 Entry、222 条联系和 32 个搜索投影，执行全部 30 个迁移并验证重复迁移 noop。
比较优化与完整读取的整个返回对象，包含内容、精确 Fragment 引用、数量、顺序、游标和关系元数据：

- 45 次分页比较，覆盖公开、包含隐私、仅隐私、相同采集时间/文档序号下的稳定次序、末页和跨隐私范围游标拒绝；
- 48 次图谱比较，覆盖当前/过期投影、停用结构、用户关系、AI 来源、隐藏边和隐私端点；
- 60 次复杂查询比较，覆盖文本、模糊匹配、来源、Snapshot、关键词、类型、领域、时间、拆分模式和两跳联系；
- 索引统计比较覆盖公开改私密、当前修订变化、退役、合成向量及模型不匹配，不调用 Provider。

每条读取路径先预热，再各测 5 次。
返回行数包含查询实际传回 Node 的所有结果行，不是 PostgreSQL 扫描行数。
峰值 RSS 是共享 Node 进程在查询边界和 1 ms 定时采样所得，受 GC 和测量顺序影响；它不是单请求分配量或 PostgreSQL 峰值内存。
smoke 只证明所选路径生效与功能等价，不推导 15,000 条规模、云端延迟或生产 SLO。

| 读取请求（各 5 次）   | SQL 返回行数：完整 → 优化 | 延迟中位数 ms：完整 → 优化 | 采样峰值 RSS MiB：完整 → 优化 |
| --------------------- | ------------------------- | -------------------------- | ----------------------------- |
| 空条件浏览，每页 3 项 | 160 → 29                  | 6.676 → 6.710              | 176.73 → 177.27               |
| 索引状态              | 2,896 → 1                 | 12.506 → 2.833             | 176.53 → 176.59               |
| 所选中心的联系邻域    | 382 → 90                  | 11.821 → 9.654             | 177.14 → 177.62               |

三个路径都减少了传回应用的行数。小样本浏览的延迟基本不变，不能据此声称所有读取都更快或进程内存下降。
本次演练共 11.245 秒，其中读取候选对照占 5.238 秒；原产品链计数先记录，附加对照不改变其含义。
一次性容器和合成外部数据均已清理。

范围是当前七个工作区的文案回归，以及知识页、来源栏、运行详情和顶部状态栏的本轮修正。
