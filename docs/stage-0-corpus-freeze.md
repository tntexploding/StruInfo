## 2. 结构解析候选

本地确定性解析得到：

- 10 个周刊文档、121 个二级标题；
- 345 个需要单独决定的内容单元，其中 310 个编号栏目条目、25 个主文或特殊专题、10 个封面单元；
- 571 个外部链接，其中 501 个位于内容单元内，其余主要是往年回顾和导航；
- 365 个图片引用，全部能归属到一个内容单元；本轮没有下载图片字节；
- 每个内容单元具有 `unitId`、期数、栏目、标题、固定提交、文件路径和起止行号。

首轮解析规则冻结为候选合同：

1. 整期周刊是来源文档，不能因为拆分条目而丢失标题、栏目顺序或相邻上下文。
2. `科技动态`、`文章`、`工具`、`AI 相关`、`资源`、`图片`、`文摘`、`言论` 仅在存在栏目级编号时按编号拆分。
3. 主文和特殊专题即使正文内部出现“1、2、3”列表，也保持为一个文档单元；内部列表以后作为子结构解析，不能误建成同级周刊条目。
4. `封面图` 是可审核媒体单元；`往年回顾` 首轮视为导航，不重复建立当前期内容单元。
5. 周刊 Markdown 是本轮直接来源。栏目指向的二级链接只是外部参考；未另行获取快照前，不能把二级页面内容说成已经保存或核验。
6. 稳定证据身份是“仓库 + 固定提交 + 文件路径 + 内容哈希 + 行号范围”。生产实现还需保存原始字节和可验证的 Fragment 定位。

本地解析脚本和派生清单只是阶段 0 工件，不是获准复用的生产解析器。阶段 1 必须用正式模块和固定 fixture 重新实现，并加入主文内部编号、缺号、重复号、无编号栏目和 Unicode 回归测试。

## 3. 保存、授权与外发边界

当前采用最小保存边界：

- Markdown 原文只保存在源码/安装目录之外的本机外部数据根，不提交、不进入构建包、不公开展示、不导出；
- 图片首轮只保存 URL、原文位置和待确认用途，不批量下载图片字节；
- 二级链接首轮只记录 URL，不抓取目标正文；
- GitHub 许可证端点在获取时返回 `404`。这不证明内容绝对不可使用，但在获得明确依据前，不授权全文、图片或派生语料的公开再分发；
- 项目 AI 供应商仍未选择。本次公开样本分析不构成生产环境外部 AI 外发授权，私人资料继续默认禁止外发；
- 保留期限、删除要求、允许下载图片的范围和公开部署边界仍需用户确认。

| T4：推荐三项用于打破技术信息茧房的内容                                | 从生物、艺术、社会、哲学或视觉资料中选择，并分别说明探索维度               | 不把“当前兴趣低”当成质量低；允许用户降低或关闭主动展示                 |
| T5：解释“为什么 Dropbox 不成功”，并展示哪些是事实、来源观点和 AI 推断 | 返回公司/产品相关事件、原文解释和有限综合                                  | 二级页面未抓取时明确降级；任何因果综合必须标为 AI 推断                 |
| T6：撤回一条错误关联并重新处理受影响知识                              | 展示原变更、授权依据、补偿修订、受影响关系和重处理结果                     | 不删除原始快照和审计历史；重复执行不产生第二份正式知识                 |

这些任务是首版验收候选，不预设答案必须显示为知识树、时间线或聊天。界面形式应由完成任务所需的信息关系决定。

## 6. 最小词表候选

### 6.1 知识类型

- `Entity`：人、组织、软件、硬件、地点或其他可复用对象；
- `Concept`：可跨资料复用的术语或机制；
- `Claim`：带陈述者、时间、范围和证据的可核验或观点性陈述；
- `Event`：带时间、参与对象和结果的变化；
- `Method`：带前提、步骤、目标或权衡的方法；
- `Framework`：由多个概念、方法或关系组成的解释结构；
- `Resource`：书、课程、网站、数据集、工具入口等资料对象；
- `Media`：被保存或引用的图片及其用途。

长文、小说和整期周刊首先是来源文档，不强迫转换成单一知识类型；它们可以保留全文级结构并派生上述知识。

### 6.2 关系类型

- `describes`、`supports`、`contradicts`、`updates`；
- `applies_to`、`depends_on`、`part_of`、`example_of`；
- `same_as_candidate`：只表示待审核同一性，不得自动等同；
- `related_to`：仅作低置信候选，不得替代能够明确表达的关系。

来源、引用、派生和修订是独立的一等边，不混入普通知识关系。

### 6.3 图片用途

- `cover`、`concept_explanation`、`data_chart`、`interface_screenshot`；
- `subject_or_example`、`decorative`、`unknown`。

图片用途必须记录依据是原文结构、用户确认还是 AI 推断。只有明确承载事实的数据图、截图或示意图才可作为证据候选；装饰图不能支持正文断言。

## 7. 成功指标候选与待确认项

知识内核首要指标建议先使用“固定任务中可被正确找回、且能返回精确来源的知识变更比例”。偏好自动化阶段再评估“每 10 分钟有效人工审核产生的、经用户接受且来源完整的知识变更数”；后者不阻塞数据库和非 AI 工作流实现。

辅助指标候选：

- 固定样本的证据定位有效率；
- T1–T6 的任务完成率与找回耗时；
- 来源型陈述的引用覆盖率和引用支持准确率；
- AI 建议接受、修改、拒绝和待定的比例，按栏目与处理类型分开统计；
- 自动写入中的严重错误数、人工纠错时间和补偿修订成功率；
- 重复导入、重试和重处理是否产生重复正式知识。

阶段 0 仍需用户确认：

1. 从代表性批次 A 中补齐足以覆盖分类、各类处理动作、拆分、连接、重组和撤回的样本；完整 28 项偏好评级后移；
2. 在知识内核可操作后记录真实任务的完成耗时，以及当前最常见的遗漏、重复处理和找回困难；
3. Markdown 本地保留期限、是否允许下载指定图片、删除要求和未来公开展示边界；
4. 公开周刊是否允许发送给未来选择的外部 AI；私人资料是否继续保持逐工作区显式授权；
5. 冲突核验是否接受“原始链接/官方资料优先，原始研究或权威机构其次，Wikipedia 只用于实体规范化和线索发现”的顺序；
6. 单个冲突的查询次数、来源数、费用和超时预算；
7. T1–T6 是否就是用户真正会执行的任务，以及首要指标是否符合实际价值判断。

在这些决定完成前，可以开始阶段 1 的来源证据、结构解析和人工审核界面合同，但不能声称偏好规则、自动入库阈值或外部 AI 数据策略已经冻结。
