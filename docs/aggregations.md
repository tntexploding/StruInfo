# 聚合实验版

聚合位于数据库左侧。先设置类型、标签、来源、日期和阅读状态，再点击“保存为聚合”。保存时填写名称，可附加一个已有主题。

各类条件共同生效。主题成员须保留当前修订，已排除的成员不加入。实验版使用文字筛选，不调用模型。

## 引用与更新

聚合保存条件、条目 ID 和更新时间。正文、标签、联系仍读取原有内容。点击聚合查看保存的成员，支持分页、阅读全文、查看联系和用所选条目生成报告。

新条目入库后，打开聚合的管理菜单，点击“保存并更新引用”重新匹配。更新前成员清单保持不变。管理菜单还可调整筛选条件或删除聚合，删除聚合保留原文。

原文删除或当前范围不可见时，相应引用不展示。隐私范围每次由用户选择，打开聚合不会自动扩大范围。聚合只包含已经形成条目的内容。

旧版保存查询仍可打开。首次更新后生成引用清单。配置沿用工作区偏好的保存和备份路径。

## 接口

- `GET /api/v1/entries/saved-queries`：读取聚合与旧保存查询。
- `POST /api/v1/entries/saved-queries`：`operation: aggregate` 按 `query` 和 `topicIds` 生成引用；传入 `viewId`、`name`、`expectedRevision`。已有改名、删除操作保留。
- `POST /api/v1/entries/aggregations/read`：传入 `viewId`、本次 `includePrivate`、可选 `onlyPrivate`、`limit` 和上一页返回的 `after`，读取引用对应的当前已确认条目。

`aggregation` 内仅保存 `topicIds`、`entryIds`、`updatedAt`。客户端不能提交正文或自行指定成员；引用由服务端按条件生成。

## 验收范围

本轮验证合成数据的条件匹配、引用保存与恢复、权限范围、版本冲突和页面渲染。真实文章上的分类质量、主题适用性、使用体验和大批量表现，待资料入库后与其他功能一起验收。
