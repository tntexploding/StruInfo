# 来源配置与接收管理

在**源管理**的唱片中选择来源。搜索固定在唱片顶部，添加来源和手动放入固定在底部。

## 基础设置

填写名称、简介、接入类型、文档隐私与来源优先级。来源颜色仅用于识别。
组件支持 RSS/Atom、公开 GitHub Markdown、声明式 JSON API、受限网页和已安装连接器。
参数编辑器只显示当前接入类型需要的地址、映射或配置引用。密钥内容不在页面保存。

## 接收设置

| 设置           | 行为                               |
| -------------- | ---------------------------------- |
| 自动检查       | 开启后按保存的安排检查来源         |
| 检查方式       | 按间隔、指定时段、采集一次或仅手动 |
| 间隔           | 控制两次检查的最短距离             |
| 检查日期与时区 | 指定星期及当天时间窗口             |
| 失败重试次数   | 0–5 次；超过次数后等待人工检查     |
| 接收参数       | 展开编辑当前组件的详细配置         |

重试等待由程序计算；成功后清除连续失败计数。
“立即检查”可用于暂停来源的单次检查。
优先级与时效要求只影响排队，不替代正文完整性检查或事实核验。
新设置只影响后续接收；已有记录保留当时的来源策略。

## AI 方案

下半区编辑来源拆分方案、标签提示和联系提示。
AI 建议先形成可编辑草稿，人可以修改。生效方案随新任务冻结，旧任务不被追溯改写。
完整规则试读、启停和格式变化处理见[来源拆分](source-splitting.md)。

## 特殊操作与接收记录

往期补收按来源、日期和数量选择，结果先待审核，不推进实时游标。
公开目录能覆盖的历史范围由来源决定。Git、JSON API 和插件暂不提供统一历史目录。

底部“接收记录与计划”向上展开，显示下一次检查、等待原因、收到的文档及正文。
可按实时检查、历史补收、手动放入等渠道筛选。
同一来源的相同正文版本不重复生成内容；正文变化保存新版本，原文和人工决定保留。
不同来源提供相同文字仍保留各自来源，主题组织时再处理重复贡献。

来源与个人方案保存在仓库外工作区，随个人数据包备份。仓库保存组件、模板和合成示例。
