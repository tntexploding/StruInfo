# 来源配置与接收管理

在**源管理**的唱片中选择来源。搜索固定在唱片顶部，添加来源和手动放入固定在底部。

## 基础设置

填写名称、简介、接入类型、文档隐私与来源优先级。来源颜色仅用于识别。
内容处理分为文章和快讯。文章审核后拆分与标注；快讯审核后直接展示，不生成条目、标签、向量和主题。
快讯在数据库页单独查看，可按标题、来源和日期筛选。拒收、待审和私密内容按原有权限控制。
组件支持 RSS/Atom、公开 GitHub Markdown、声明式 JSON API、受限网页和已安装连接器。
参数编辑器只显示当前接入类型需要的地址、映射或配置引用。密钥内容不在页面保存。
接收范围可填写包含词与排除词，每行一项。普通词匹配标题，含 `/` 的项匹配地址。规则保存在来源配置中。

## 接收设置

| 设置           | 行为                               |
| -------------- | ---------------------------------- |
| 自动检查       | 开启后按保存的安排检查来源         |
| 检查方式       | 按间隔、指定时段、采集一次或仅手动 |
| 间隔           | 最短 1 分钟；新来源默认 5 分钟     |
| 检查日期与时区 | 指定星期及当天时间窗口             |
| 失败重试次数   | 0–5 次；超过次数后等待人工检查     |
| 接收参数       | 展开编辑当前组件的详细配置         |

重试等待由程序计算；成功后清除连续失败计数。
“立即检查”可用于暂停来源的单次检查。
优先级与时效要求只影响排队，不替代正文完整性检查或事实核验。
新设置只影响后续接收；已有记录保留当时的来源策略。

## AI 方案

下半区编辑来源拆分方案、标签提示和联系提示。
AI 建议先形成可编辑草稿，人可以修改。生效方案随新任务冻结，旧任务不被追溯改写。
完整规则试读、启停和格式变化处理见[来源拆分](source-splitting.md)。

## 特殊操作与接收记录

往期补收按来源、日期和数量选择，结果先待审核，不推进实时游标。
公开目录能覆盖的历史范围由来源决定。Git、JSON API 和插件暂不提供统一历史目录。

底部“接收记录与计划”向上展开，显示下一次检查、等待原因、收到的文档及正文。
可按实时检查、历史补收、手动放入等渠道筛选。
同一来源的相同正文版本不重复生成内容；正文变化保存新版本，原文和人工决定保留。
不同来源提供相同文字仍保留各自来源，主题组织时再处理重复贡献。

## 正文与访问限制

RSS 和网页接收支持同站路径、`www` 地址迁移，最多跟随三次跳转。每次检查目标地址，跨站跳转仍需更新来源配置。
开启全文补取后，标题、摘要和末尾带“阅读全文”的预览会获取文章页。完整的订阅正文直接保留。
明确的付费提示或网页付费标记会转为待核对，停止自动审核与整理。长预览同样过滤，普通订阅邀请保留。
原始响应、补取正文与人工决定分别保存。人工仍可明确接受或拒绝。
快讯优先审核收到的原文，不自动把链接展开成长文章。正文不完整时待人工核对，仍可手动补取。

## Git 文档

路径可以填单个 Markdown 文件，或以 `/` 结尾的目录，如 `book/`。目录包含子目录的 Markdown 文件，每个文件独立保存原文和来源。
一次最多接收 64 个变化文件，4 路下载。超过一批时保存进度，下次检查继续同一提交。目录读取使用固定提交和文件版本，无变化时跳过正文下载。删除上游文件不会删除已接收资料。
单文件上限 1 MiB。目录索引超过上限或被 GitHub 截断时停止，不把不完整目录记为完成。

## MCP 接收器

接入类型选择“MCP / 插件”，接收器选择“MCP 接收器”。组件标识为 `plugin.mcp-receiver.v1`。
配置引用填环境变量名，例如 `SOURCE_MCP`。用 `SOURCE_MCP_FILE=/run/secrets/source_mcp` 指向只读挂载的 JSON 文件，也支持直接在 `SOURCE_MCP` 中保存 JSON。

```json
{
  "serverUrl": "https://mcp.example.org/mcp",
  "headers": {"Authorization": "Bearer REPLACE_WITH_OWNER_TOKEN"},
  "tool": "list_documents",
  "arguments": {"limit": 20},
  "recordsPath": "data.items",
  "externalIdPath": "id",
  "titlePath": "title",
  "bodyPath": "content",
  "canonicalUriPath": "url",
  "publishedAtPath": "time",
  "recordLimit": 32,
  "pagination": {
    "cursorArgument": "cursor",
    "nextCursorPath": "data.next_cursor",
    "hasMorePath": "data.has_more"
  }
}
```

服务地址、工具、参数和字段映射均保存在个人配置中。仅调用配置指定的接收工具。支持 HTTPS Streamable HTTP、JSON 与事件流响应；每次最多保存 32 条，按标识和内容版本去重。
正文格式 `bodyFormat` 可选 text、html、markdown。缺少原文链接时可配置含 `{id}` 的 `canonicalUriTemplate`。无时区日期使用配置中的 `timeZoneOffset`；默认 UTC。`success` 可指定响应成功条件，如 `{"path":"status","value":200}`。
`pagination` 可省略。配置后按由新到旧的目录续拉，读到上次接收位置停止；首次接入只接收当前页。每次最多读取三页、保存 32 条，未完成的页码和位置随成功批次保存，下一分钟继续。失败保留上次进度，暂停和重试限制继续有效。接收器只调用指定工具。个人配置及密钥保存在仓库外，随部署挂载到运行接收任务的服务。
金十可配置为此接收器的一个来源，工具及字段见[官方接入说明](https://mcp.jin10.com/app/doc.html)。

来源与个人方案保存在仓库外工作区，随个人数据包备份。仓库保存组件、模板和合成示例。

## JSON 快讯

JSON API 支持原文链接模板（`{id}`）、当前时间请求参数、Unix 秒发布时间和 HTML 正文。
未提供标题的记录使用正文开头作为显示标题，原文保留。配置版本字段后，阅读量等附加字段变化不会重复接收。
这些参数位于源管理的接收参数窗口。来源地址和字段映射保存在个人配置中。
配置“快讯续拉”后，按末条记录的 ID、时间或响应中的下一页向前读取，直到上次成功接收的位置。首次接入只读取当前页。
单批最多 32 条。未完成的游标随成功批次保存，下一分钟继续；失败保留原游标。暂停状态和重试次数继续有效。
上游列表提前截断或游标不前进时显示接收异常，保留断点。接口本身未保留的消息无法补齐。
`timeZoneOffset` 指定无时区日期的时区。`paidContentPath` 指定付费标记字段，值为 1 或 true 的记录跳过。
`querySignature` 支持公开查询参数的 SHA1→MD5 校验，参数与算法保存在来源配置中，不含账号密钥。
`requestAsAjax` 用于要求 Ajax 请求头的公开 JSON 列表。
快讯续拉和普通分页配置择一使用。停机期间的漏接从实时断点接续，历史文章补收仍需单独发起。
