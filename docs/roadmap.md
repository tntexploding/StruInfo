## 总体策略

先用一个真实信源证明“获取 → 可追溯 AI 摘要 → 批准 → 找回”的价值，再扩展为稳定日报与推送。知识树、时间线、混合问答、云端和自动发现均按真实任务与依赖逐步加入，不作为第一次验证的前置条件。

## 阶段 0：冻结真实场景

目标：用实际资料决定 MVP，而不是继续抽象设计通用平台。

交付物：

- 一个长期跟踪主题；
- 一个主要信源、一个备选信源和至少 10 条历史内容；
- 一份人工制作的理想日报；
- 5–6 个真实的找回、比较、判断或维护任务，不预设必须用树、时间线或问答完成；
- “值得入库 / 只需报告 / 应当忽略”的标注样本；
- 当前人工流程的时间、遗漏和重复信息基线；
- 现有 QQbot 的最小集成方式；
- 对本地知识、外部模型和云端部署边界的选择。

退出条件：可以人工完整模拟一次“获取 → 去重 → 总结 → 日报 → 批准 → 查询 → 推送”，并定义一个首要成功指标。

## 阶段 1：一个信源的价值探针

目标：不先建设知识平台，用最薄纵向切片验证 AI 日报是否真的降低阅读和整理成本。

候选范围：

- 默认仅监听本机回环地址的单用户浏览器界面，写操作使用本地会话认证和 CSRF 防护；
- 一个真实 RSS/Atom 信源，允许手工触发或固定每日获取；
- `Endpoint → FetchRun → Resource → Snapshot → Fragment → Candidate → KnowledgeRevision` 基础链路；
- AI 标题、摘要、相关原因和修订级引用；
- 最简日报、批准、拒绝、纠错与已保存列表；
- 关键词找回、原文回看、任务状态、错误记录和批准幂等。

退出条件：对 5–10 条真实内容，AI 整理没有增加总体操作成本；所有正式来源型知识都能回到证据；用户愿意继续处理下一批内容。

## 阶段 2：稳定日报与只读推送

目标：形成一条可连续每天运行、可主动触达用户的第一可用版本。

候选范围：

- 加入第二个真实信源；
- 可恢复调度、游标、重试、原始响应哈希、规范正文哈希和变化检测；
- 候选池、重复判断和相关性排序；
- 新快照生成更新候选，并把受影响总结标为待复核，不静默覆盖旧知识；
- 日报生成、统计窗口、用户时区和发送记录；
- 通用、版本化 HTTP 接口和带签名、防重放、至少一次投递的 Webhook；
- QQbot 只展示摘要和指向已登录网页的批准链接；暂不从 QQ 直接写知识；
- 根据阶段 0 的真实任务，选择基础搜索、知识树、时间线或本地问答中的最小必要部分。

退出条件：连续运行一周无静默漏抓或重复入库；重复 Webhook 不造成重复展示或副作用；用户愿意继续订阅并能从报告中选出值得入库的内容。

## 阶段 3：实时网络与私人知识混合查询

目标：让一次查询可以安全地区分并综合已有私人知识和当前网络信息。

候选范围：

- 本地知识、实时网络和混合查询；
- 在线结果的临时证据、引用和一键转候选；
- 带出处自然语言回答，清楚显示本地快照、实时网络和证据年龄；
- 在线查询范围、费用、超时和每日预算限制；
- 查询结果只有保存快照后才能转为正式候选。

退出条件：本地与在线答案来源清晰可辨；重要结论有修订级引用；证据不足时系统不会伪装成确定答案。

## 阶段 4：单用户云端部署

目标：让服务可从公网安全访问，并保持数据、调度和推送可恢复。

候选范围：

- 登录、TLS、私有默认权限、密钥管理和外部模型策略；
- 附件迁移、备份恢复、资源配额、费用预算和运行监控；
- 稳定资源/工作区 ID、API 与事件版本；
- 调度游标、候选状态和投递状态在重启或恢复后保持一致。

退出条件：未认证用户无法读取私人内容；备份恢复不会重新批量入库或推送；密钥不进入内容与普通日志。

如果阶段 0 确认云端访问是第一版硬要求，本阶段可提前，但不能省略阶段 1 的价值验证。

## 阶段 5：本地项目与交互式 QQbot

目标：在云端或其他部署形态下，安全联动用户的本地 HTTP/WS 服务和客户端。

候选范围：

- 版本化 HTTP 命令/查询、WebSocket 实时进度和可靠 Webhook；
- 本地桥接程序主动向云端建立认证出站连接；
- 能力级授权、目录白名单和资源限制，不提供通用命令执行；
- QQ 身份绑定、最小权限、防重放、危险操作确认和审计；
- QQbot 查询候选并执行明确的一键批准/拒绝命令。

退出条件：云端无法访问未授权本地资源；断线后可通过 HTTP 恢复状态；重复命令和事件不产生重复副作用。

## 阶段 6：受控主动智能

目标：在信噪比与可信边界得到验证后，提高 AI 的自主性。

候选范围：

- 在指定主题、站点或查询范围内自动发现信源；
- 个性化相关性、新颖度和信源偏好；
- 交叉印证、冲突和过期提示；
- 白名单与规则自动入库；
- 自动化预算、每日数量上限、暂停、解释和回滚；
- 根据历史反馈调整报告和候选排序。

开放规则自动入库的候选门槛：试运行样本中至少 95% 的结果无需拒绝或回滚；未达到时继续使用一键批准。

## 各阶段都必须保持的约束

- 原始来源、AI 产物和正式知识分层；
- 任何重要结论可追溯；
- 高影响动作需要明确权限；
- 外部内容不能提升自己的工具权限；
- 所有异步工作可恢复、可重试且可观察；可重试写操作幂等，至少一次事件投递由接收方去重；
- 稳定 ID、工作区边界和 API 版本从第一版保留；
- 不以复杂图谱、更多模型或更多连接器代替真实使用价值。
