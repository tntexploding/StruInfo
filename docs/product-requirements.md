## 0. 当前数据隔离与发行约束

所有者已经完成首轮外部真实数据使用审核。无论本地或云端工作区是否含有真实数据，以下边界持续成立：

- 真实文档、条目、偏好、知识、Blob、数据库、导出、备份、运行配置和 secret 只进入包体外位置；
- 不把个人数据、公开真实语料或历史工作副本加入 Git、镜像或 fixture；
- 自动化测试只使用合成、无个人含义且测试结束后清理的数据；
- 是否把本地个人数据迁移到云端，必须由所有者另行明确选择，不能随代码发布自动发生。

发行和后续开发仍须运行单元、集成、构建、合成浏览器、制品与容器验证，并优先修复当前公开路径可复现的 `PRODUCT_BLOCKER`。真实使用授权不等于跳过工程质量门。

本约束改变当前运行材料，不改变 Entry、Evidence、隐私、个人数据包或 Provider 的产品语义。

## 1. 方向演进

v0.1 将 StruInfo 定义为可追溯的知识结构化工作台。

v0.2 将产品扩展为持续采集外部信息、由 AI 主动加工、形成可核验知识、支持本地与在线查询，并能向用户或其他项目推送结果的个人信息枢纽。

当前基线进一步明确：**知识摄取与维护是产品内核，日报、QQbot、公共 API 和云端部署是建立在内核之上的后续交互与运行形态。** 首版首先验证异构资料能否被保存、筛选、结构化、关联、维护和找回，而不是先验证推送渠道。

## 2. 产品定义

### 一句话定位

> StruInfo 是一个来源可追溯、AI 可增强的个人知识摄取与维护系统：它保存指定信源或手工资料的原始证据，通过用户操作、确定性规则或 AI 提案拆分、比较、关联、重组和维护版本化知识，并通过网页提供审核、接管、浏览和带出处检索。AI 不可用时，核心知识操作与搜索仍然成立。

长期形态仍是可在线使用的个人信息枢纽，可以加入定时采集、实时网络查询、知识树、时间线、报告、外部项目接口和消息推送；这些能力不再定义首个核心闭环。

本文中的“在线”需要区分三层：

1. **能够按策略访问互联网信源和核验来源**：核心能力；
2. **通过浏览器使用**：首个产品切片，初期只需在本机或受控局域网访问；
3. **由公网云服务器托管**：核心逻辑稳定后的部署目标。

### 核心任务

> 当我面对周刊、论文、项目文档、设计大纲、教程、评论文章或其他资料时，我希望系统完整保留可用证据，并允许我或确定性工具把资料分类、拆分、连接和重组为长期知识。AI 可以自动提出合适粒度、与既有内容比较并建立联系，但不会拥有另一套数据库语义。系统应在发现重复、补充、冲突或结构问题时可解释地维护知识，并在我查询时结合来源、关系、版本和时间返回结果；随着反馈积累，AI 可以逐步接管低风险工作，但我始终拥有最高权限的手工操作、暂停、纠错、撤回和重处理入口。

### 核心价值

StruInfo 的价值不是“收藏更多网页”，而是降低五种成本：

1. 获取和保存异构资料及其来源证据的成本；
2. 判断信息量、趣味性、探索价值和噪声的成本；
3. 将资料拆分、合并和组织为长期知识的成本；
4. 发现重复、冲突、过期内容和结构缺口的成本；
5. 重新查询、核验、更新和复用知识的成本。

系统还要主动抵抗单纯偏好学习造成的信息茧房：既学习用户当前关心什么，也保留独立、可配置的探索策略，用邻域扩展、跨领域连接、基础缺口、新兴信号和观点多样性拓宽知识面。

### 产品边界

它是：

- 私有、单用户优先的知识摄取、维护与检索工作区；
- 以来源快照、文档结构和证据锚点为可信基础的 AI 工作流；
- 同时保留原始资料、文档结构、正式知识和控制记录的分层系统；
- 在不配置 AI、Embedding 或外部模型时仍可完整导入、分类、编辑、关联、重组、检索和导出；
- 能够在用户或版本化策略授权范围内逐步提高自动化程度的系统。

它不是：

- 不保留出处的 AI 摘要流；
- 只把文档切成向量块的问答外壳；
- 无限制抓取互联网的通用爬虫；
- 让网页内容或模型输出直接指挥工具、扩大权限或修改数据库的自治 Agent；
- 强迫论文、周刊、项目文档和框架教程采用同一种知识粒度的系统；
- 以点击率、既有偏好匹配率或单一“真值/兴趣分数”优化全部行为的推荐系统；
- 首版就支持所有格式、全部媒体理解和所有消息平台的集成平台。

## 3. 三条核心闭环

### 3.1 当前资料进入与条目评价闭环

```text
手工 Markdown / 固定 Git Markdown / 本地 Markdown、文本、HTML 或带文字层 PDF
  → 保存包体外原始 Blob、来源身份和不可变 Snapshot
  → 用确定性 profile 生成 DocumentNode / Fragment
  → 用户选择 Snapshot，按 section 结构物化当前 InformationEntry
  → 在“标签”页编辑正文、三维标签和有用/有趣五档评价
  → 聚合文档标签并重建可解释 Entry 联系
  → 通过确定性查询找回 Entry 和精确来源
```

旧的“完整处理 / 拆分处理 / 压缩处理 / 仅保留来源 / 忽略 / 人工判断”准入动作、
判断原因和手工联系意图已经退出当前产品路径。既有数据库行只用于兼容，不能再把这条历史
审核流描述成活动 UI 或 Entry 生成前置条件。

### 3.2 知识形成与维护闭环

```text
已保存的资料或内容单元
  → 按结构生成可追溯 InformationEntry
  → 用户 / 确定性规则 / AI 提案标注内容、类型和领域关键词
  → 聚合文档标签并建立选择性关联
  → 确定性相似联系直接成为可编辑图谱边
  → 按需深化为对象、概念、观点、事件、方法、资源和用户关系
  → 与既有知识比较
  → 新增 / 修订 / 关联 / 记录冲突 / 请求人工处理
  → 用户关系和其他语义写入由用户操作或版本化策略授权
  → 保留来源、规则版本、用户 override 和回滚路径
```

模型供应商适配器不能直接写正式知识。自动入库表示应用根据用户批准的策略调用正式知识用例，不表示模型绕过权限、校验和审计写数据库。

### 3.3 查询、反馈与后续联动闭环

```text
用户在网页提出结构化搜索或问题
  → 选择私人知识 / 实时网络 / 混合范围
  → 从知识、关系、证据、来源和时间维度检索
  → 必要时在允许范围内获取新的网络证据
  → 返回可解释的记录；启用 AI 时可进一步综合并逐项引用来源
  → 用户纠错、接管或要求重新处理
  → 反馈进入偏好、探索和知识维护记录
```

日报、周报、HTTP/WS、Webhook、QQbot 和其他客户端是该闭环的后续入口或出口，不改变知识库核心的权限和证据规则。

## 4. 首个用户与已确认场景

首版面向单个用户，通过本机浏览器验证资料入库、审核、知识浏览和搜索。

首个真实信源确定为[阮一峰《科技爱好者周刊》GitHub 仓库](https://github.com/ruanyf/weekly)：

1. 以仓库中的原始 Markdown 周刊文件作为主要输入；
2. 记录仓库、分支、路径、Git commit、内容哈希、期数、发布时间和获取时间；
3. 以栏目中的独立条目作为主要人工筛选单位，同时保留整期文档结构；
4. 首版记录条目中的外部链接，但不批量抓取全部二级来源；
5. 图片先保存或引用允许保存的原始版本，关联所在内容，并标注封面、解释图、数据图、截图、示例、装饰或未知用途；
6. 先由用户标记处理结果，积累样本后由 AI 提议可读、版本化的筛选规则；
7. 通过筛选的内容可以由用户或确定性规则拆分、比较和关联；AI 随后通过相同的变更提案边界自动增强，低风险新增和非破坏性更新可按策略提交，高影响操作转人工；
8. 第一阶段只要求网页端完成核心验证，报告、QQbot 和外部项目接口后移。

周刊 Markdown 是首版实际捕获和引用的直接来源。条目指向的外部页面是“来源所引用的二级来源”；在系统尚未获取并保存该页面前，不能把周刊的转述冒充为外部页面原文，也不能声称已核验二级来源。

首批至少选择 10 期历史周刊，并对其中的独立条目建立人工标注集。仓库公开可读或自称“开源”不自动等于获得任意保存和再分发权；正式保存全文、图片或公开部署前仍需记录来源授权、保留范围和再分发边界。

## 5. 功能需求

### 5.1 信源、采集与快照

系统需要：

- 管理用户手工添加的 Git 仓库路径、网页、RSS/Atom、API、文件或文本来源；
- 为每个订阅信源保存抓取频率、用户时区、启停状态和最后成功游标；
- 对抓取任务记录开始、完成、失败、重试和结果数量；
- 使用内容哈希、来源标识和发布时间等信息避免重复处理；
- 在内容变化时创建新快照，而不是覆盖旧版本；
- 保存规范链接、最终链接、获取时间、发布时间、作者/站点及允许保存的原始内容；
- 对 Git 来源保存仓库、ref、提交身份、路径和原始文件哈希，不只保存随时间变化的分支 URL；
- 在无法保存完整网页时，至少保留可核验的引用片段、必要元数据和内容哈希；
- 区分“允许获取这个信源”“这份资料值得处理”和“允许提交哪些知识变更”，不能用一个开关代表全部授权；
- 遵守站点授权、访问限制、频率限制、保留期限和内容使用边界，不绕过登录或反爬措施。

自动发现分级开放：

| 等级 | 行为 | 产品阶段 |
| --- | --- | --- |
| L0 | 用户手工粘贴、上传或提交 URL | 最早支持 |
| L1 | 定时读取用户明确订阅的 Git、RSS、API 或网页信源 | 精确 GitHub Markdown、公开 RSS/Atom、声明式 JSON API 与通用连接器/远程文档入库底座已实现；网页随后接入 |
| L2 | 在用户指定主题、站点或查询范围内发现候选信源/内容；新信源默认需确认后订阅 | 信噪比验证后 |
| L3 | 系统自主扩展来源并探索开放网络 | 远期，不作为默认能力 |

内建读取器与受信任插件必须使用同一获取协议：连接器只能返回有界来源文档和游标，不能直接写 Evidence、Entry、标签、联系、正式图谱或 AI 提案。主程序负责隐私、去重、Snapshot、失败恢复和游标提交。插件配置属于包体外个人数据；凭据只允许来自运行环境或专用凭据引用，不能进入 Git、正文、普通日志或个人数据包。

### 5.2 异构文档与分层保存

当前实现保持四层活动数据和一层兼容数据：

| 层级 | 当前职责 | 状态 |
| --- | --- | --- |
| 证据层 | 原始/规范化 Blob、Resource、不可变 Snapshot、来源和哈希 | 已实现 |
| 文档结构层 | DocumentNode、Fragment、媒体引用、顺序和精确位置 | 已实现 |
| 条目层 | 当前 InformationEntry、三维标签、两项评分、Document 标签和选择性联系 | 已实现，是普通工作主线 |
| 正式知识层 | Entry 节点、自动相似边与用户关系；闭合关系语义、维护说明和来源核验状态；历史 Knowledge 表兼容保留 | M1J 当前图谱维护入口已实现 |
| 检索派生层 | 绑定当前 Entry revision 的本地词项、可选公共向量、词法/语义/混合召回、评估与公开证据 RAG | M1K 已实现；可全部重建且不进入个人数据包 |
| 控制层 | 外部个人标签偏好、版本化联系策略、当前联系 override；旧准入/判断/变更集行 | 前三项活动，旧行仅兼容 |

当前导入接受手工 Markdown、固定 Git Markdown，或用户明确选择的一份本地文件/最多 20 份本地文件批次；本地文件类型限于 `.md`、`.markdown`、`.txt`、`.html`、`.htm`、`.pdf`。HTML/PDF 原始字节作为外部 Blob 证据保存，服务端生成单独文本投影供现有结构与拆分管线使用。导入时选择 `commonmark-v1` 或
`ruanyf-weekly-v1`，由确定性解析器保存完整结构。拆分页让用户选择尚未生成 Entry 的
Snapshot：可以直接按 section 确定性物化，也可以在本地查看全文和精确 Fragment，在既有
边界或 Fragment 内 Unicode 标量边界合并/重新拆开连续分组、编辑标题后一次提交。对于公开 Snapshot，用户还可显式发起
OpenAI Fragment 分组提案，并在逐组核对精确本地正文后人工应用；没有 Provider 时人工与
确定性物化均完整可用。

人工分组必须按来源顺序完整覆盖全部 section Fragment；客户端不提交 Entry 正文，服务端从
不可变证据重建。确定性、人工和 AI 接受共用同一空 Snapshot 原子边界，已经物化的结构不会被
覆盖。拆分前全文修改由 M1H-3A/B 以“唯一当前草稿 → 显式确认 → 新的不可变派生 Snapshot”实现；M1H-4A/B 提供版本化本地 section/相邻短段合并规则及显式预览/应用。来源重排和任意脚本/自定义解析器仍未实现。已有 Entry 的人工结构重组由 M1H-2A/B 提供。

普通 Entry 更新只保留一个当前成品态和并发版本，不重复保存每次中间输入；原始 Snapshot、
Fragment 与 Blob 仍不可变。

用户在导入时可以标记隐私文档。系统保存完整原始和规范化字节，默认 Entry、联系、查询和
完整文档通道都排除隐私内容；只有当次显式选择才扩大范围。查询页在 Entry 分页之外提供独立
完整隐私文档结果，正文仍从包体外 Blob 按需读取，并可通过 Evidence 详情打开全文。该范围
不是加密或多用户授权。

### 5.3 信息价值、偏好与探索

当前普通 Entry 只保存两个互不替代的人工值：

- `usefulnessScore`：有用程度，1–5；
- `interestScore`：有趣程度，1–5。

它们不生成准入动作、拆分命令、正式知识或事实可靠性判断。内容关键词、类型关键词和领域
关键词也分别保存；个人快捷标签、自动提取开关、排除词、URL 域名开关、用户确认别名和版本化
联系权重/阈值保存在包体外偏好文件。策略保存使用期望修订并重建自动候选，不覆盖逐对人工
控制或正式图谱关系。旧 Curation 的相应评分与有效分类词只在迁移 `000011` 中一次性投影，之后
不再由旧审核命令更新。

信息密度、广度、深度、新颖性、探索价值、噪声和认知成本仍是长期产品方向。
`ExplorationPolicy` 已实现；`EntryPreferenceProfile` 当前已完成外部闭合状态、个人数据包
兼容、确定性建议、有界只读试运行、窄公共操作和标签页次级编辑面板。这些能力只有在真实
使用证明能降低人工成本，且拥有清晰解释和覆盖路径时才继续获得后续自动化权限。

### 5.4 AI 主动加工

AI 可以参与：

- 内容清洗、分段和语言识别；
- 文档类型判断和处理计划生成；
- 标题、摘要以及压缩条目生成；
- 对象、概念、事件、方法、框架、关键陈述和关系提取；
- 与历史知识的重复、补充、冲突、过期和结构缺口判断；
- 生成新增、修订、关联、冲突或人工处理的知识变更提案；
- 在允许的站点和预算内搜索冲突证据，并保存实际使用的页面和片段；
- 从人工反馈总结偏好规则和探索建议；
- 本地/在线混合查询规划与带证据回答；
- 在限定范围内提出新信源、跟踪建议以及后续报告编排。

每次 AI 加工必须记录：输入快照或知识版本、处理计划、输出、时间、供应商、模型、提示/规则版本、参数、用量、审核或策略授权状态、警告和错误。AI 生成内容不能只链接网页首页，必须能追溯到实际输入片段或输入集合。

外部网页、文档和消息一律视为不可信数据，不能借其中的文字改变系统规则、扩大工具权限或触发未授权操作。

#### 5.4.1 无 AI 基线

无 AI 仍是完整的正式运行方式，已实现：

- 手工 Markdown 与固定 Git Markdown 导入、不可变证据和确定性结构解析；
- 用户选择文档，可先保存一份当前全文草稿并确认成派生 Snapshot，再以确定性规则或本地人工 Fragment/Unicode 标量区间分组物化 Entry，最后编辑当前正文、三维标签和两项五档评价；
- 确定性关键词候选、用户快捷标签、排除词、URL 过滤和确认别名；
- 文档标签聚合、可解释 Entry 联系及人工增强/削弱/屏蔽/恢复；
- 文本子串、结构、来源、时间、隐私和一至两跳联系查询；
- 含 61 张工作区表、引用 Blob 字节和偏好的个人数据包导出/空工作区恢复；
- 最高匹配 Entry 中心、有界图谱/列表、边来源、用户关系编辑和三种隐私范围。

尚未实现的是来源重排、任意脚本或自定义解析器规则、集合/树/时间线、第二向量 Provider、私密向量/RAG、
Provider 自主在线查询和通用自动维护。系统不得因为这些未来能力缺席而把当前工作区显示为故障。

### 5.5 入库自动化与权限等级

ADR 0012 已实现 Provider-neutral ProcessingRun/提案信封、最近任务读取和期望版本取消。ADR 0013、0014、0015 在同一 OpenAI Responses API 边界上分别实现一个公开 Entry 的 `tags`、用户选择公开 Entry 对的 `association` 和用户选择公开 Snapshot 的 `split` 提案：用户显式启动，Provider 返回闭合载荷，用户接受后才转换为既有 Entry revision、graph edge command 或 Entry materialization；拒绝不修改领域状态。私密内容在网络调用前拒绝，模型没有直接写表、证据或图谱命令。没有 Provider 配置时，所有导入、确定性物化、标签、联系、查询和正式图谱关系编辑仍由用户显式操作或确定性逻辑完成。

ADR 0011 已把 M1E-2 定义为 Entry 节点、确定性相似边与用户关系共同组成的图谱。现有
AssociationProjection 达到可见条件后可直接进入图谱，不需要逐边人工确认；用户可以编辑、
屏蔽/删除或恢复，且人工 override 优先于后续重建。用户创建或编辑语义关系仍经过唯一命令
边界；模型、来源适配器和后台任务只能产生提案，不能直接改表。其他自动化仍按人工操作、
范围授权、自动分流和委托维护逐级开放；合并、重要冲突裁决、大规模重排和扩大外部权限
保持人工确认。

### 5.6 可信度与来源说明

每条来源型知识、AI 总结和查询答案都应展示可点击出处。系统不得把下列维度压成一个含义模糊的“真值分数”：

| 维度 | 回答的问题 |
| --- | --- |
| 可追溯性 | 能否回到当时的来源快照和准确片段？ |
| 来源评价 | 该站点、作者或机构在此领域是否值得信赖？ |
| 解析/抽取置信度 | 系统是否正确读取了文本、图片或实体？ |
| 关联置信度 | 提到的对象是否真是知识库中的同一对象？ |
| 交叉印证 | 是否有独立来源支持、补充或反驳？ |
| 新鲜度 | 证据和结论距当前时间多久，是否可能过期？ |
| 审核状态 | 待审核、用户确认、有争议、已驳回或已撤回？ |

“用户确认”只表示用户接受该记录或确认来源确实这样声称，不自动等于客观事实为真。

任何来源评价都必须记录评价维度、适用领域/范围、评价者、依据和评价时间；“某来源在某领域通常可靠”不能自动传递成“该来源的每条陈述都正确”。

信息价值、兴趣和探索评分不属于事实可靠性。界面和排序不得用“用户感兴趣”暗示内容更真实，也不得用“来源可靠”暗示内容一定值得向用户主动展示。

### 5.7 知识组织

[ADR 0011](adr/0011-association-derived-formal-graph-edges.md)将所有者看到的“正式知识”定义为
以现有 `InformationEntry` 为节点、由自动相似联系和用户关系共同构成边的可编辑关系图谱。
Entry 的稳定身份、当前正文、三维标签、隐私事实和精确 Fragment 来源继续作为节点数据，
不复制成第二套普通内容对象，也不要求每个短 Fragment 先生成 `KnowledgeItem`。

当前普通 Entry 工作流必须分开保存：

- 内容、类型和领域三个标签维度；
- 有用程度和有趣程度两个独立五档值；
- 来源、Fragment 输入、隐私和拆分方式；
- 可重建关联分数与人工增强、削弱、屏蔽或恢复状态。

图谱边有两种来源：确定性 AssociationProjection 直接成为对称的 `similarity` 边；用户可另行
创建带名称和方向的关系，或编辑自动边的解释。持久关系还保存闭合的关系语义、最多 500 个
Unicode code point 的维护说明，以及 `unreviewed / source_checked / needs_review` 来源核验状态。
自动边表示“计算上相似、值得一起查看”，读取时必须显示为 `similarity / calculated`，不等于
经过人工核验的事实断言。`source_checked` 只表示用户回看过两端精确来源，不证明陈述客观为真，
也不替代时效、适用范围、冲突或来源可靠性判断。界面和接口必须显示边是自动计算、用户编辑、
用户创建还是 AI 提案经人工接受。用户屏蔽/
删除自动边后保存持久 block，重建只可更新底层分数与解释，不能覆盖用户编辑或让被删除的边
重新出现；用户可显式恢复并查看当前投影。

“正式知识”页面必须提供：

- 简单的确定性 Entry 搜索，并把最高匹配结果作为中心节点；
- 一个紧凑的候选列表，允许用户改选中心；
- 围绕中心按需加载的有限直接邻域，而不是默认渲染整个工作区；
- 点击节点查看 Entry 当前内容、标签、隐私状态和精确来源；
- 点击关系查看其自动/用户/AI 来源、相似分数与解释（如适用）、关系语义、名称、方向、维护说明和来源核验状态，并可分别打开两端精确来源、编辑、屏蔽/删除或恢复；
- 与图谱表达相同节点和边的可搜索列表/树模式，供键盘、辅助技术和低性能设备使用；
- 公开、包含隐私和只看隐私三种当次范围，并在中心选择和关系遍历前应用。

普通“查询”页面继续负责完整过滤、稳定分页和结果比较；“正式知识”页面的搜索只负责选择
图谱中心并查看其正式上下文。关系标签和未来图谱布局偏好都是外部工作区中的个人数据，不能
编译进源码、迁移 seed 或真实 fixture。

历史 `KnowledgeItem`、`KnowledgeRevision`、`KnowledgeRelation` 及其来源行继续兼容
保留，但不自动成为新页面节点，也不授权恢复已删除的 M1C 编辑器。未来若需要把某些历史知识
映射到 Entry 图谱，必须通过独立迁移和真实工作区验证。AI 未来仍只能提出关系候选；ADR 0011
允许自动进入图谱的只是现有确定性相似投影，不是模型直接写库。

### 5.8 冲突核验与知识维护

发现冲突时，系统先区分：真正的事实矛盾、时间变化、适用范围不同、定义/单位/翻译不一致，以及来源陈述与 AI/用户推断不一致。

需要网络核验时，系统应：

- 使用用户允许的站点、主题范围、费用和请求预算；
- 支持按领域配置优先信源，但不把 Wikipedia 或任何单一站点硬编码为所有领域的最终权威；
- 保存搜索词、搜索时间、访问页面、来源快照和实际支持判断的片段；
- 记录 AI 为什么认为冲突已解决、仍然并存或需要人工判断；
- 只有在授权策略允许且不涉及高影响裁决时自动提交修订，否则建立 `ConflictCase` 转人工。

系统不得静默覆盖旧知识。被新证据修正的知识仍保留历史修订、原有依据和替代关系。

### 5.9 时间线

时间线至少需要区分：

- `published_at`：来源发布时间；
- `captured_at`：系统获取时间；
- `event_time`：内容所描述事件发生的时间；
- `valid_from / valid_to`：某项知识的适用时间；
- `created_at / updated_at`：知识入库和编辑时间。

默认时间线优先使用事件时间；无法确定时回退到发布时间，并明确显示所用时间类型。网页更新只表示出现新快照，不直接证明旧知识失效或错误。

时间值需要记录时区、精度以及是否由 AI 推断。发布时间只能作为显示回退，不能被写成事件时间。

### 5.10 本地、在线与混合查询

查询必须允许用户明确选择范围：

- **私人知识**：已经正式进入 StruInfo 的知识及其关系、证据和历史；
- **实时在线**：当前从网络获取、尚未正式入库的临时资料；
- **混合查询**：先利用私人知识，再用在线资料补充或核验。

首个切片先支持对私人知识按关键词、对象、来源、时间、关系和处理状态找回，并允许查看 AI 为什么创建、修订或关联某项知识。

结果界面必须区分私人快照与实时在线结果，显示快照年龄和获取时间。实时结果只有在保存来源快照、证据片段和获取时间后，才能进入待处理变更或正式知识库。

自然语言回答中的重要结论必须带引用；证据不足时应明确说“不足以判断”，并将 AI 推断与来源陈述分开呈现。

本文暂时把“私人知识”解释为存放在 StruInfo 私有知识库、区别于互联网即时结果的内容。外部模型是否能够接收其中的内容仍按工作区显式授权；要求资料只能存在用户设备时，需要本地桥接与联邦检索。

“私人知识库”与用户显式标记的“隐私文档”不是同一个范围：前者指整个本地工作区，后者是在其中额外默认隐藏的内容。普通本地搜索不会因为运行在私人工作区就自动包含隐私文档；每次扩大到该范围都需要明确勾选，并使用与普通搜索不同的分页游标范围。

### 5.11 图片与其他媒体

第一版对图片只要求保存、关联和标注用途，不要求 OCR 或视觉知识提取：

- 保存或引用允许保留的原始图片、来源 URL、内容哈希、类型、尺寸和所在文档位置；
- 关联到文档、内容单元、证据片段或知识条目；
- 用枚举或版本化词表标注封面图、概念解释图、数据图表、操作截图、示例、装饰或未知；
- 区分用途来自原文说明、AI 推断还是用户确认，并为 AI 推断保存置信度；
- 装饰图片不能作为事实证据；图片不可用时仍保留替代文本和来源关系。

后续 OCR、多模态理解、音频和视频必须作为派生处理保留区域或时间锚点，不能覆盖原始媒体。

### 5.12 日报、周报与提醒

报告属于核心知识闭环稳定后的交互入口。后续实现时需要支持：

- 用户时区、发送时间、统计窗口、主题和信源范围；
- 新颖度、重复项、当前兴趣和探索价值的分维度排序；
- 按知识变化、主题、对象或事件聚合，而不是简单拼接摘要；
- 每个报告项包含摘要、展示原因、探索原因、出处、已有知识关联和操作入口；
- 查看知识变更、调整处理规则、忽略一次、降低相似内容展示和转人工审核；
- 推送失败重试、投递记录、静默时段和幂等处理；
- 周报基于一周信息重新综合，而不是机械合并七份日报。

报告可以作为审核或接管入口，但不能成为正式知识唯一入口，也不能把推送成功与知识处理成功混为一个状态。

### 5.13 外部项目与 QQbot 联动

外部接口在核心入库、审核和搜索可用后开发。知识库核心不包含 QQ 平台专属逻辑；QQbot 是薄适配器，通过通用接口获得摘要、链接、查询结果或待处理项。

接口职责建议为：

- HTTP：提交资料、创建信源、查询任务、搜索知识、处理审核和管理规则；
- WebSocket：展示处理进度和即时界面更新；
- Webhook：可靠通知 `review.required`、`ingest.completed`、`ingest.failed`、`knowledge.updated`、`digest.ready` 等事件。

所有可能被外部系统重试的写操作必须支持幂等键；异步操作返回任务 ID；WebSocket 断开后仍能通过 HTTP 恢复最终状态；Webhook 采用至少一次投递，事件包含事件 ID、时间戳、资源 ID 和版本，并支持签名、重试和接收方去重。

QQ 中的普通自然语言不能直接执行批量批准、合并、删除等高权限操作。QQ 身份需要绑定到 StruInfo 用户/工作区，敏感正文应通过受控链接查看。

### 5.14 在线与云端运行

首版按单用户私有服务设计，但从一开始保留：

- 稳定资源 ID 和工作区 ID，不把本机绝对路径作为业务标识；
- 长任务可恢复、可重试且幂等；
- API 和事件版本；
- 配置、密钥与业务数据分离；
- 应用代码、外部运行配置、工作区数据、Blob/导出/备份和秘密存储分别管理；
- 附件通过逻辑资源 ID 引用；
- 数据删除、导出、备份和恢复能力；
- 模型调用范围、费用、延迟与数据外发边界可配置。

所有个人知识、词表、分类、偏好、策略、信源、保存查询、用户提示词、快照、附件、导出和备份必须存放在工作区数据库或源码/安装目录之外的外部数据根。它们不得硬编码、提交到 Git、进入正式 fixture、前端 mock、迁移 seed、构建资源、安装包或容器镜像。

仓库只允许保存配置 schema、没有真实值的示例和合成测试数据。实际运行配置从包体外加载；启动时解析规范绝对路径并拒绝把个人数据根放在 Git 工作树、源码目录、安装目录或容器非持久层内。具体边界由 [ADR 0006](adr/0006-external-configuration-and-personal-data-isolation.md) 固定。

同一应用构建必须能够通过更换包体外运行配置、选择稳定工作区或导入版本化 Workspace Bundle 来切换并重新读取另一套资料、偏好和用户控制数据，不得要求修改源码、重新构建或复制个人资源到 Git。首版允许用受控重启/重新打开实现该能力；候选配置与工作区必须完整验证后才激活，失败不得形成数据库、Blob 和工作区身份的混合状态。

若未来云端服务需要与本地服务器、目录或客户端通信，应由本地桥接程序主动建立受认证的出站连接，只暴露用户明确授权的能力和目录；不要求用户把局域网服务直接开放到公网。

## 6. 候选最小数据语义

以下是需求层对象词典，不表示每一项都已实现。当前活动对象包括 Resource/Snapshot、DocumentNode/Fragment、InformationEntry 当前态、Entry 关键词、当前 Document 标签、Entry 联系投影/控制、Provider-neutral ProcessingRun/提案信封、外部偏好和个人数据包；旧 Curation/Knowledge 对象只兼容保留，其余对象均属于未来范围。精确状态见[当前项目状态](current-project-state.md)。具体表和约束以[知识核心架构](knowledge-core-architecture.md)和迁移为准：

| 对象 | 职责 |
| --- | --- |
| `Watch / Endpoint` | 用户订阅或提交的入口，如 Git 路径、RSS、API、网页栏目、本地目录或手工输入 |
| `FetchRun` | 对一个入口的单次获取；记录游标、结果、错误和重试 |
| `Resource` | 一篇文章、一条 API 记录或一个文件等可独立引用的内容 |
| `Snapshot` | 某个 Resource 在某次获取时的不可变版本；URL 会变化，快照才是证据 |
| `DocumentNode / Fragment` | 快照中的文档、章节、段落、列表项、字符区间、DOM 区域、页码或图片区域 |
| `MediaAsset / MediaUsage` | 原始媒体身份、所在位置、允许保留的字节或引用，以及封面、解释、图表、截图、示例、装饰或未知用途 |
| `InformationEntry / Revision` | 从具体 Snapshot 形成的首要检索单元；保存稳定身份、顺序、标题路径、正文、证据位置、拆分版本和沿袭 |
| `EntryKeywordAssignment` | 分别保存自由内容关键词、一个类型关键词和一个主领域加最多两个副领域，以及人工/规则/AI 来源 |
| `DocumentTagRevision` | 从全文倾向和 Entry 覆盖率聚合的可修改文档标签及算法版本 |
| `AssociationProjection / Override` | 可重建的相关性分项、基础分和算法版本，以及不会被重算覆盖的人工增强、削弱或屏蔽决定 |
| `VocabularyTerm / ContentClassification` | 工作区自定义内容类别及其版本化指派，例如小说、论文、教程或工具介绍；不决定处理动作 |
| `IntakeDecision` | 对资料或内容单元作出的完整处理、拆分、压缩、仅保留来源、忽略或人工判断动作 |
| `Assessment` | 信息价值、偏好、探索、噪声、来源或抽取等分维度评价；记录类型、范围、评价者、依据和版本 |
| `PreferenceProfile` | 从用户反馈总结出的当前偏好及其样本、规则和版本 |
| `ExplorationPolicy` | 独立于当前偏好的探索类型、预算、展示规则和版本 |
| `ProcessingRun` | 当前已实现的 Provider-neutral 任务状态：稳定身份、来源、五阶段进度、隐私范围、期望版本取消、错误码和可选 Snapshot 目标 |
| `ProcessingProposal` | 保存 split/tags/association 类型、目标、摘要、状态和精确 Fragment 输入；闭合载荷位于 typed 子表，用户接受后转换为既有 Entry/图谱命令 |
| `KnowledgeChangeSet` | 一次处理提出的新增、修订、关联、冲突或人工审核变更，以及授权来源和提交结果 |
| `Candidate` | 尚未获用户或策略授权、存在不确定性或必须人工审核的知识变更 |
| `KnowledgeItem / Revision` | 有稳定 ID 和不可变修订的实体、概念、陈述、总结、推断、笔记、事件、方法或框架 |
| `Citation` | 某个具体 Knowledge Revision 或 Relation Revision 对原始 Fragment 的直接引用 |
| `Derivation` | 某个具体总结/推断修订由哪些 Fragment、Knowledge Revision 或处理运行加工而来 |
| `Relation / Revision` | 具有稳定 ID，并以不可变修订表达端点、方向、类型、限定条件、审核状态和依据的知识关系 |
| `ConflictCase` | 互相矛盾或表面矛盾的知识、证据、分类、网络核验过程和处理状态 |
| `TreePlacement` | 知识在一个或多个树视图中的位置，不复制知识本身 |
| `Collection / SavedView` | 对既有知识的有序组合或保存查询，不复制规范修订 |
| `SearchProjection` | 从当前修订、别名、关系、来源和分类重建的搜索索引；可删除后重建 |
| `AutomationPolicy` | 用户批准的自动化动作、范围、阈值、预算、有效期、版本和暂停状态 |
| `Operation` | 对外可查询的长任务、阶段、进度、错误、尝试和关联资源 |
| `Digest / Delivery` | 报告内容、统计窗口、发送渠道、状态和幂等记录 |
| `Integration / Event` | 外部系统凭据范围、订阅事件和投递状态 |

必须保持的语义边界：

- 网页链接不等于网页快照；
- 直接捕获的周刊来源不等于尚未获取的外部链接来源，转述不等于二级来源原文；
- 整份资料不等于其中每个内容单元都获准进入正式知识；
- 当前兴趣不等于信息价值，探索价值不等于事实可靠性；
- 内容分类不等于处理动作，处理动作不等于知识类型或审核状态；
- 用户批准一份资料不等于授权模型执行合并、删除或冲突裁决；
- 原文摘录不等于来源陈述，来源陈述不等于 AI 总结，AI 总结不等于 AI 推断；
- 来源版本不等于知识版本；
- 在线搜索结果不等于已入库知识；
- AI 变更提案不等于已提交的知识修订；
- 知识树父子关系不等于事实关系；
- 发布时间、事件时间、抓取时间和入库时间不能混用。

内容变化检测需要同时区分原始响应哈希与规范正文哈希，避免广告或版式变化制造大量假更新。发现新 Snapshot 后，应生成差异、受影响知识和 `KnowledgeChangeSet`，标记旧总结“待复核”或“可能过期”；只有得到用户或策略授权后才能提交新修订，不得静默改写或撤销既有知识。

## 7. 最早价值验证与候选第一版

首个验证不以日报或外部接口为中心，而以“资料进入后能否形成正确、可追溯、可维护并能找回的知识”为中心。知识图谱画布、完整时间线、混合在线问答和推送均不作为核心逻辑第一次验收的前置条件。

#### 7.1.1 M1C 可运行核心检查点（历史证据）

本节记录已经退役的 M1C 应用运行时曾完成的纵向验证，不是当前路由或 UI 清单。当前活动能力以[项目状态](current-project-state.md)和 ADR 0009 为准。

为了尽快得到可使用的程序，MVP-0A 曾经过一个不改变最终语义的可运行检查点。该检查点只要求：

1. 从包体外选择或上传一份固定周刊 Markdown，并把来源身份、原始 Blob、结构、Fragment 和媒体引用写入真实 PostgreSQL；

### 7.1.2 M1E-1 当前成品态与个人数据包

ADR 0008 将普通五步文档工作流收敛为“不可变原始证据 + 一个当前数据库成品态”。Entry、
Document 标签和关联控制更新时覆盖当前值，只保留并发版本号，不再为每次中间修改复制
历史正文、关键词或控制行；正式 Knowledge 的语义修订历史不受影响。

“标签”是唯一普通人工审核页：它同时保存有用/有趣两个独立五档值、确定性内容标签、
类型/领域维度、个人快捷标签、排除词与别名规则。大小写差异自动归一；中英文同义等语义
合并必须由用户确认别名。处理意图、判断原因和手工联系退出当前工作流。

为兼容已经完成的旧人工审核，000011 在删除旧修订列之前进行一次确定性投影：当前
`information_density` / `current_interest` 五档值分别进入 Entry 的有用/有趣评分，当前有效
分类词进入内容关键词；已有 Entry 当前值优先，迁移不重新执行旧处理意图，也不生成正式知识。

拆分、标签、联系、查询分别拥有独立页面组件和页面级控制器；共享只限于无业务所有权的展示
组件与纯标签映射。每类异步读取使用单调请求标识，迟到响应和卸载后的响应不得覆盖当前页面状态。

新导出是完整个人数据包，包含数据库状态、所有引用 Blob 字节及工作区偏好；文件仍只位于
外部数据根，秘密与运行配置继续排除。旧 Bundle 保持可读。查询提供公开、包含隐私和只看
隐私三种当次范围。主导航在查询之后提供“正式知识”页；M1E-2 已按 ADR 0010/0011 接通最高匹配中心、有界图谱/列表、来源标记、用户关系编辑和精确来源。

ADR 0009 删除旧 Manual Curation、正式 Knowledge 写入/读取和旧 Knowledge 检索运行时及其
adapter、HTTP/Web 接线。旧迁移、历史表和个人数据包分区继续保留，以便现有外部工作区导出
与恢复；未来正式知识功能必须经过 M1E-2 新边界，不能依赖已删除的隐藏 API。

### 7.1.3 M1E-2 Entry 正式关系图谱

### 7.1.8 M1E-4A 人工 Fragment 分组

任意 Fragment 内字符级边界、重排、拆分前保存全文修改、自定义解析/拆分规则和已物化 Entry 的结构重组不属于 M1E-4A。

### 7.1.9 M1E-4B Fragment 内人工边界

### 7.1.10 M1E-5A 本地文本文件导入

ADR 0018 已把单份本地 `.md`、`.markdown` 或 `.txt` 文件接入现有导入页。浏览器只读取用户明确选择/拖入的文件，检查基础文件名、严格 UTF-8、空文本/NUL 和现有 1 MiB 上限，不发送本机目录路径。无前置文字时，canonical Base64 解码后的字节必须与外部 Blob 中的 Snapshot 原始字节一致；默认来源身份使用基础文件名与 SHA-256。用户填写前置文字时，界面必须明确这是组合后的新 Snapshot。

服务端只允许 `uploaded_file` 使用 Base64 请求字段，并在写入前完成闭合解码；随后继续使用既有 Evidence、Blob、CommonMark 结构、Fragment、隐私传播和空 Snapshot Split 队列。失败重试复用同一 command/resource/snapshot/capturedAt 身份，成功后才刷新列表和生成下一份身份。M1E-5A 本身不接受二进制格式；后继 M1E-5B 通过独立投影边界接入 HTML/PDF。M1H-5A/B 在浏览器内把同一逐文件边界编排为显式多文件会话队列；目录监视、云同步或仓库内上传目录仍不在该能力。

### 7.1.11 M1E-5B 本地 HTML/PDF 文字层导入

ADR 0019 已把单份 `.html`、`.htm` 和带文字层 `.pdf` 接入同一 Import → Split 主链。浏览器发送原始文件的 canonical Base64；服务端保留完整原始 Blob，并在任何数据库写入前生成 UTF-8 Markdown 投影。HTML 只提取标题、语义正文、列表、引用、预格式文本、表格行、链接和图片替代文字，跳过脚本、样式、表单、嵌入/隐藏内容且不访问网络。PDF 按页读取已有文字层并加入页标记。

原始文件与文本投影都遵守现有 1 MiB 边界。HTML 必须是严格 UTF-8；PDF 必须有合法签名、无需密码且至少有可用文字。可选前置文字只加入 HTML/PDF 文本投影，不改写所选原始文件。隐私、来源身份、幂等导入、Fragment、人工/确定性/AI Split 和个人数据包语义保持不变。首版不声称 OCR、版面复原、表格/公式/图片理解，也不包含 Office、目录监视或远程网页抓取；后续 M1H-5 仅补上显式最多 20 文件的会话队列。
### 7.1.12 M1F-1 可解释本地词法查询

### 7.1.13 M1F-2 查询联想与结果比较

### 7.1.14 M1F-3 证据约束的 AI 综合查询

ADR 0022 与 M1F-3 已实现这一窄开发边界。用户先执行普通 Entry Query，得到非空公开结果后，才可以显式触发次级“AI 综合当前结果”动作。输入、结构过滤、Association 遍历、隐私、排序和结果选择仍完全由既有确定性查询决定；Provider 不搜索数据库、不改写查询、不选择关系，也不访问网络工具。

服务端以同一语义查询重新取得前 8 条公开当前 Entry，为它们建立 `E01`–`E08` 请求内句柄，并向既有 OpenAI Responses API adapter 发送标题、有界正文摘录和三维公开标签。单条摘录最多 4,000 个 Unicode 标量，完整证据包最多 24,000；超出时必须显式标记截断。任何包含隐私或只看隐私范围的请求都必须在 Blob 读取和 Provider 调用前拒绝，完整隐私文档通道绝不进入证据包。

Provider 只返回闭合的答案、`supported / partial / insufficient` 证据状态、最多 12 条 claim 及其证据句柄和最多 6 条限制说明。应用必须拒绝未知句柄，并把合法句柄映射回本地 Entry 修订、摘录和精确来源操作；模型不得提供稳定数据库身份。页面清楚标明 AI 来源、模型、Prompt 版本、截断和局限，首次调用前说明公开结果文本将发送给配置的 OpenAI。查询语义或隐私范围变化后旧综合立即失效，迟到响应不得覆盖新范围。

首版答案只存在当前页面会话，不写 ProcessingRun/Proposal、Entry、Association、正式图谱、偏好、数据库或个人数据包。它复用现有 OpenAI 环境配置、native `fetch`、`store: false`、无 tools 和现有超时，不增加 SDK、答案历史或 Web 搜索。ADR 0043 后，综合会复用当前词法/语义/混合检索作为公开证据召回，即形成有界 RAG；没有 Provider 时，本地 Query 必须保持完整可用并诚实显示综合不可用。

### 7.1.15 M1G-1 确定性 Entry 探索策略

ADR 0023 与 M1G-1 实现偏好学习之前的第一条独立探索路径。探索不混入普通搜索结果，不改变匹配、排序、计数、分页或游标，也不在输入和筛选变化时自动运行。用户从当前可见查询结果选择一个锚点后明确启动；服务器只从其当前可见直接 Association 中选择页外候选。

外部 `ExplorationPolicy` 独立于 Association 权重和未来 `PreferenceProfile`，默认关闭，保存 0–50% 当前页份额以及邻域扩展、跨领域连接、偶然发现三个开关。份额换算结果最多 12 条。候选先按隐私范围过滤，再排除当前页、屏蔽和过期联系；三类分别稳定排序并轮转取样。每条必须显示可证明的原因、联系强度、候选依据、来源范围和精确来源，不能暗示事实关系、语义等价或 AI 推荐。

### 7.1.16 M1G-2 版本化 Git 信源订阅

ADR 0024 与 M1G-2 实现 L1 的第一条窄路径：用户可以在导入页保存一个精确公开 GitHub 仓库中的单个 `.md` 或 `.markdown` 文件订阅。订阅包含稳定身份、标签、repository/ref/path、解析 profile、来源别名、隐私标记、15 分钟至 7 天间隔以及默认关闭的定时开关。保存使用期望修订；手动检查不要求先开启定时执行。

### 7.1.17 M1G-3 可解释 Entry PreferenceProfile（已实现）

ADR 0025 把现有人工有用/有趣评分和内容、类型、领域标签收敛为第一版可读偏好规则。M1G-3A 已实现默认关闭、带修订、最多 64 条规则的闭合 Profile，并保存在包体外个人偏好文件、随完整个人数据包携带；旧文件和旧包补为空 Profile。每条规则只作用于有用或有趣一个维度，只匹配一个规范化内容标签、类型或领域，并明确表示偏好或降权方向及 1–5 权重；两个维度不得合并成一个总分，也不得覆盖 Entry 上的人工评分。

M1G-3B 已实现候选与试运行纯核心。候选规则只能在用户明确操作后由本地确定性统计产生。4–5 分、3 分和 1–2 分分别作为正向、中性和负向观察；同一特征/维度至少有三项显式评分且一侧比另一侧多至少两项时才形成候选。建议权重为正负样本差的绝对值并封顶 5，候选最多 64 条，显示聚合计数和仅限本次请求的 Entry 身份；用户接受后才进入 Profile。

试运行最多评估 100 个稳定排序的当前 Entry，分别显示有用和有趣规则匹配；格式错误、Profile 修订过期和显式 Entry 修订变化不会被静默替换。规则建议和试运行不保存正文、来源 URL、样本身份、搜索历史、点击行为或拒绝候选，也不改变普通查询、Entry、标签、联系、图谱或 ProcessingRun。公开范围默认；包含隐私必须当次显式选择且完全本地，不调用 Provider。

### 7.1.32 M1M 单机生产运行与维护（已实现）

[ADR 0045](adr/0045-operational-production-baseline.md) 提供非 root 多阶段 Dockerfile、普通 runtime 与高权限 maintenance 分离的 Compose、外部单行 secret 文件、独立迁移/pg-boss schema 准备、runtime grant、维护预检、完整个人数据备份和同工作区空库恢复。应用继续复用现有 live/ready、结构化日志和优雅关闭，不增加业务迁移、依赖、个人数据或第二个运行时。

M1M 是可操作的单机生产代码边界。2026-08-27 已在本地 Docker 与 disposable PostgreSQL 18.6 上用合成数据通过迁移、队列准备、runtime grant、健康、备份、同 workspace 空库恢复和重启。`v0.1.0` 在此基础上加入运行镜像瘦身、浏览器安全响应头和宿主认证反向代理示例；目标云端仍需落实域名、证书、防火墙、备份保留和监控。项目代码采用 MIT License。这些门只阻断对应部署/分发，不重新打开已完成的五步产品主线。

### 7.2 MVP-1：偏好学习与每周自适应摄取

MVP-0 证明知识核心可用后，再让系统持续处理该信源并逐步学习用户偏好：

> 每周发现新一期 → 保存提交身份和快照 → 分维度评分 → 高确定性内容自动处理、低价值内容自动忽略、不确定内容人工审核 → AI 维护知识并记录探索推荐原因。

候选增量包括：

- 可恢复的每周调度、Git 游标、重试和变化检测；
- 从人工样本提议 `PreferenceProfile` 和筛选规则，并由用户批准、试运行和版本化；
- 独立的 `ExplorationPolicy`，支持邻域扩展、跨领域连接、基础缺口、新兴信号、观点多样性和偶然发现；
- 信息价值、偏好、探索、噪声和不确定性的分维度评估；
- 自动分流的阈值、数量/费用预算、暂停、解释和回滚；
- 发现冲突时建立 `ConflictCase`，并在允许站点范围内保存网络核验证据；
- 用户始终可以覆盖决定、修正规则并重新处理受影响内容；
- 基础 JSON 导出，覆盖来源、文档结构、知识、引用、规则、变更集和冲突。

核心第一版暂不包含：

- 开放网络自主发现信源；
- 未经用户启用策略的自动入库；
- AI 自动合并/删除核心词条或裁决重要冲突；
- 任意网页、登录态页面和复杂反爬站点；
- 全库知识图谱画布和预先设计的复杂本体；M1E-2 只实现有界中心邻域；
- 多用户协作和多租户商业化；
- StruInfo 内部直接实现 QQ 协议；
- 云端直接访问用户局域网；
- 让网页内容触发任意工具或代码执行。

7. AI 增强没有增加总体操作成本，用户愿意继续处理下一批内容，且至少一个首要指标优于无 AI 的当前做法。

### 8.3 MVP-1 验收

1. 系统按每周计划发现同一周刊仓库的新一期；休眠、重启和重复运行不会漏抓或重复提交知识。
2. AI 从人工样本生成可读的偏好规则；规则未获用户启用前不参与自动决定，启用后记录版本和适用样本。
3. 新内容分别显示信息密度、深度/广度、新颖性、当前兴趣、探索类型、噪声和不确定性，不用单一总分掩盖原因。
4. 高确定性内容按策略处理，低价值内容按策略忽略，中间区域进入审核；用户能解释、覆盖和重新训练每种结果。
5. 用户拒绝内容时可以区分“已经知道”“质量低”“暂时不需要”“不感兴趣”等原因，不会把所有拒绝都学习成领域排斥。
6. 探索策略在当前偏好之外保留可配置的内容份额，并解释邻域扩展、跨领域连接、基础缺口、新兴信号或观点多样性等展示原因。
7. 冲突网络核验只访问允许范围，保存查询和证据；无法可靠解决的冲突不会被自动裁决。
8. 抓取、解析、AI、知识提交和网络核验失败有独立且明确的状态，不会被一个“已完成”掩盖。
9. 用户能够导出来源、文档结构、知识、引用、偏好/探索规则、变更集和冲突映射。

## 9. 非功能与安全要求

- 抓取任意 URL 时防止 SSRF：禁止访问未授权的本机、内网和云元数据地址，并限制跳转、大小、类型和超时；
- 外部内容只作为数据，防止提示注入改变系统指令或工具权限；
- 抓取、解析、AI 处理、规则授权和知识提交应支持幂等；事件允许至少一次投递，但重复事件不得产生重复副作用；
- 密钥不出现在报告、消息正文或普通日志中；
- 所有自动知识写入、外部写入与推送具有身份、策略版本、范围和审计记录；
- 设置抓取并发、频率、深度、每批处理数量、网络核验和 AI 预算上限；
- 支持来源与知识删除、保留期限、导出和备份；
- 个人数据和实际运行配置不进入 Git、源码/安装目录、测试 fixture、构建包或容器镜像；
- 保存全文、图片和二级来源前记录授权与保留策略；公开部署或再分发不能以“公开可读”代替内容许可；
- 本地服务默认只监听回环地址；所有写接口仍需认证及浏览器侧 CSRF 防护，监听非本机地址必须显式开启；
- 公网在线模式必须提供认证、传输加密和私有默认可见性；
- 本地桥接只能执行能力级授权操作，不提供通用命令执行；目录授权需防止路径规范化或符号链接绕过；
- `PreferenceProfile` 与 `ExplorationPolicy` 分开授权、版本化和回滚；不得只优化点击率或既有偏好匹配率；
- 任何自动化都能暂停、解释、接管和通过补偿修订回滚，不删除既有审计历史。

## 10. 已确认与进入实现前待冻结

已经确认：

- 首个真实信源是阮一峰科技周刊 GitHub 仓库；
